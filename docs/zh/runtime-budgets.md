# 运行时任务预算

这些设置作用于网页版使用的 Python 运行时，以及 Python 屏幕操作器。
Android 原生 Agent 和桌面版的 DeepSeek Harness 对话循环使用各自的执行引擎，
不受这些设置控制。

## 设置任务预算

在 `config/config.toml` 中添加以下设置。限制默认均为 0，表示不启用。
这里的数值是配置示例，不是模型价格。

```toml
[agent]
max_context_tokens = 32768

[agent.budget]
max_total_tokens = 200000
max_seconds = 600
max_cost_usd = 0
input_usd_per_million = 0
output_usd_per_million = 0
```

`max_context_tokens` 限制主 Agent 单次输入请求的近似 token 数，包括系统提示、工具定义、
历史推理和图片。它与 `llm.max_tokens` 输出限制分开计算。文本按每四个 UTF-8 字节
估算一个 token，含 JSON 开销并向上取整，每张图片另计 4096 token。配置的单位是
token，不是字节。这种估算不依赖供应商，但会因模型和语言而有误差，不是精确分词器，
也不保证符合所有视觉模型的上下文窗口。完成调用后会采用供应商报告的实际用量；
设置上下文限制时应给输出留出空间。

输入过大时，工具结果副本保留带标记的头尾内容，再按完整调用组移除旧历史。
当前任务的用户请求、系统指令和工具参数不截断。仍放不下时，任务会在调用模型前
说明上下文预算不足。保存的对话保留原文。每次缩短工具结果都会写入 INFO 日志，
记录调用编号及缩短前后的字符数，不包含工具输出正文，便于排查模型遗漏细节的原因。

`max_total_tokens` 累计一次 `run()` 中全部模型调用的输入和输出。请求发送前预留
估算输入，并缩小输出上限；有供应商用量时采用其报告。token 和费用上限都没设时，
请求发出前不做估算，输出上限保持调用方给的值；供应商报告的用量照常计入。没有用量、请求失败或流被
取消时，保守计入输入估算和完整输出额度。Agent 和操作器发起的重试共享预算，
嵌套的手机与电脑操作器沿用父任务预算，下一轮任务重新计数。

`max_seconds` 包含工具执行和等待审批。超时通过协作取消停止任务；阻塞执行或忽略
取消的工具无法强制撤销。token 或费用预算耗尽后，不再启动工具，也不额外付费
请求模型总结；已经完成的纯文本回答仍可返回。

启用费用限制时，请填写自己的每百万 token 美元费率，并覆盖任务可能使用的所有
模型，包括屏幕操作模型。缓存输入按完整输入费率估算。费用上限非零而两个费率均
为零时，配置会被拒绝。客户端内部隐藏的供应商重试、embedding、图片、视频及其他
付费工具不在此计费范围；这不是供应商账单的硬性封顶。

独立操作器可使用 `[gui.budget]` 下的同名设置；在运行时 Agent 内执行时，父任务的
`[agent.budget]` 优先。目前通过 TOML 配置，各端没有新增设置控件。
设了上限、或被上限停下的那一轮，会在审计日志里写一条 `task_budget` 记录；没设上限的
任务不往日志里加东西。`MuseAgent.last_budget` 两种情况下都给出用量和停止原因，
操作器结果也携带相同计数，供评测报告使用。
