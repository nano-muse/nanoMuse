# 运行时任务预算

任务预算用于限制一次任务的模型用量、执行时间和估算费用。本文设置适用于网页版使用的 Python 运行时（执行智能体任务的程序），以及用 Python 实现的屏幕操作器。Android 原生智能体和桌面版 DeepSeek Harness 对话循环使用各自的执行引擎，不受这些设置影响。

## 配置任务 {#configure-a-task}

在 `config/config.toml` 中加入以下配置。各项限制默认为 0，表示关闭限制。示例数值用于说明预算设置，并非模型价格。

```toml
[agent]
max_context_tokens = 32768

[agent.budget]
max_total_tokens = 200000
max_seconds = 600
max_cost_usd = 0
input_usd_per_million = 0
output_usd_per_million = 0
```

`max_context_tokens` 限制主智能体一次输入请求的近似 token 数。token 是模型计量文本和其他输入的单位，不能直接等同于字数。这里计入系统提示词、工具定义、历史推理和图片，与模型输出上限 `llm.max_tokens` 分开。文本按每四个 UTF-8 字节估算一个 token，向上取整，也包含 JSON 格式本身的开销；中日韩字符按每字 1.5 token 计算，因为一个字符通常占三个字节，实际分词约为一至两个 token。每张图片另计 4,096 token。配置单位是 token，而不是字节。这是一种不依赖具体模型的近似算法，并非精确分词器，误差会随模型和语言变化，也不能保证符合视觉模型的上下文窗口（一次可处理的输入与输出容量）。调用完成后，服务商报告的用量会替代估算值。设置输入限制时，应为配置的输出预留空间。

请求过大时，运行时先缩短工具结果的副本，保留带标记的开头和结尾，再按完整对话组移除较早的交互。当前任务的用户请求、系统指令和工具调用参数都保持完整。如果这样仍超出限制，运行时会在向模型发送请求前停止，并说明上下文预算不足。保存的对话仍保留原文。每次缩短工具结果时，都会写入一条 INFO 日志，记录调用 ID 及缩短前后的字符数，不记录工具输出正文，便于追查模型为何遗漏细节。

`max_total_tokens` 累计一次 `run()` 内所有模型调用的输入和输出。发送请求前会预留估算的输入用量，并根据剩余额度降低 `max_tokens` 输出上限；服务商返回用量后再用实际报告替换。没有设置 token 和费用限制时，发送前不做用量估算，也不修改调用方设置的 `max_tokens`，但仍累计服务商报告的用量。服务商未报告用量、请求失败或流式响应被取消时，会计入估算输入和完整输出额度。智能体和操作器的重试共享同一任务预算；嵌套的手机或电脑操作器继承父任务预算，新一轮任务则重新计数。

`max_seconds` 包括工具执行时间和等待审批的时间，审批就是等待你决定是否允许操作。到达上限后，运行时通过协作式取消请求各部分停止。忽略取消信号或正在执行阻塞操作的工具，无法被强制撤销。一旦 token 或费用上限耗尽，就不会启动新工具，也不会额外付费请求模型收尾。不过，已经发出的请求如果完成了纯文本回答，仍可以返回这段回答。

使用费用上限时，需要填写你自己的**每百万 token 美元费率**，并采用足以覆盖任务中所有模型的较高费率，包括「手」使用的屏幕操作模型。缓存输入也按配置的完整输入费率估算。如果费用上限非零，而输入和输出费率都为零，配置会被拒绝。客户端内部未向运行时披露的服务商重试、embedding（文本向量化）调用、图片、视频以及其他付费工具，都不在这套统计范围内。预算限制的是应用发起的请求，不能作为服务商账单的费用上限保证。

独立运行的操作器使用 `[gui.budget]` 下的同名字段；在运行时智能体的一轮任务内调用时，优先使用 `[agent.budget]`。这些限制通过 TOML 文件配置，各 App 不另外提供设置控件。设置了限制的任务，或因限制而停止的任务，会在审计日志中写入 `task_budget`；没有设置限制的任务不会新增这类记录。无论是否设置限制，都可以通过 `MuseAgent.last_budget` 获取用量计数和停止原因。操作器的执行结果也包含同样的计数，供评测报告使用。
