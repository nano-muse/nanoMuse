# 一个账号连接所有设备 {#一个账号-所有设备}

在手机、电脑和网页控制台上登录同一账号，就能让这些设备协作：你在一台设备上提出要求，另一台设备负责执行；需要确认的操作会在你发起请求的设备上显示审批卡片；主要聊天也会在设备之间同步。本页以公共中继 `cloud.nanomuse.cn` 为例，从安装手机 App 开始，说明如何让手机调用 Mac 编译项目。中继是负责账号和设备间通信的服务器。设备通信协议见 [hub.md](hub.md)，账号及免费额度见 [cloud.md](cloud.md)，自己部署中继见 [self-hosting.md](self-hosting.md)。

## 1. 手机 {#_1-the-phone}

安装 App，参见 [android.md](android.md) 或 [ios.md](ios.md)。首次打开时先登录账号，可用手机号或邮箱接收验证码；设过密码后，也可用密码登录。这次登录会同时配置 nanoMuse Cloud 服务商、设置 → 模型 中的四项模型，以及与其他设备的连接。

在 设置 → nanoMuse Cloud → 设备 中配置这台手机：

- 「让其他设备能找到这台手机」让手机保持连接，以便其他设备向它发送请求。开启期间会显示一条静默通知。
- 「允许其他设备操作这台手机」决定其他设备是否可以让手机执行 shell 命令（在终端中运行的命令）、读取文件、截图或执行任务。关闭后，手机仍能查看并操作其他设备。
- 「这台手机的名字」是你向智能体指定设备时使用的名字，建议简短，例如「pixel」或「小米」。

下方列表会显示账号内的所有设备，以及它们是否在线或上次在线的时间。

iPhone 只能执行 iOS 允许的操作，包括 `info`、`open`、`notify` 和 `task`，分别用于设备信息、打开链接、通知和任务。iOS 不提供 shell、文件或屏幕操作。

## 2. 电脑 {#_2-the-computer}

从[最新版本](https://github.com/nano-muse/nanoMuse/releases/latest)下载并安装 nanoMuse 桌面版，然后登录同一账号。每个平台都有对应的安装包，已包含「手」所需的运行时，也就是执行屏幕操作的后台程序，详见 [desktop.md](desktop.md)。几秒后，电脑会出现在手机的设备列表中，手机也会出现在桌面版侧栏的「设备」页。在 设置 → 设备 中给电脑命名，例如「mac」或「desk」。

其他设备首次请求操作这台电脑时，电脑会弹出确认卡片，可选择「允许一次」或对该设备「总是允许」。开启 设置 → 设备 中的「免询问远程控制」后，账号内任何设备发起的操作都不再弹出这张卡片。

电脑也可以只运行 Python 运行时，执行 `nanomuse serve`，再在它提供的网页版中登录同一账号，即可按同样方式加入。参见 [app.md](app.md) 和 [cli.md](cli.md)。

## 3. 网页控制台 {#_3-the-web-console}

打开 `https://cloud.nanomuse.cn/app/`，登录同一账号。控制台会显示账号内的设备和对话。选择一台设备后即可输入消息，需确认的操作会显示为审批卡片。自己部署的中继也在其 `/app/` 路径提供相同的控制台。

## 4. 试一试 {#_4-try-it}

在手机上可以说：「在 mac 上列一下下载文件夹」「让 desk 把 ~/proj 编译一遍，把最后二十行日志发我」「电脑截个图给我看」「给电脑发个通知：该睡了」。

在电脑上可以说：「在手机上截个图」「让 pixel 上的 Muse 读一下最近一条通知」「给 pixel 发个通知：编译完成」。

在控制台中，先选择设备，再输入要求即可。

如果交代的是一整项工作，例如「编译项目，再把日志发给我」，目标设备上的 Muse 会在独立对话中执行这项任务。任务可能持续几分钟，执行步骤会实时显示在你当前的聊天中。

## 5. 审批 {#_5-approvals}

删除、发送、付款或修改系统之前，智能体会先请求你的确认，这称为审批。卡片显示在你输入要求的设备上；远端 Muse 提出的审批请求也会传回这里。

从一台设备操作另一台设备，还需要目标设备的使用者单独允许，配置见上面的第 1、2 节。如果目标设备上无人确认，发起请求的设备会收到未获允许的结果。

## 6. 设备之间会同步什么 {#_6-what-follows-you}

登录后，主要聊天会同步到其他设备。打开「同时同步旁聊」后，旁聊也会同步。这两个开关都位于各设备的「数据控制」中，详见 [sync.md](sync.md)。

智能体的名字和形象属于账号，各设备会使用同一份。在一台设备上登录连接器后，其他设备会显示「已在〈设备〉上连接」，点一下即可在当前设备上也登录该服务，详见 [hub.md](hub.md)。模型则由每台设备分别选择，各自使用自己的 设置 → 模型 配置。

## 7. 使用自己的中继 {#_7-your-own-relay}

按 [self-hosting.md](self-hosting.md) 可以在一台小型 VPS（租用的虚拟服务器）上运行相同的中继服务。手机在登录页的「使用其他服务器」中填写地址；桌面版在配置文件 `cordis.patch.yml` 中填写；网页控制台则位于该中继的 `/app/`。

同一账号下的所有设备必须连接同一中继，因为设备列表和对话都保存在那个中继上。
