# 形象工作室

智能体的脸默认是随附的小龙，直到你开口要换一张；灵感卡不会自行改变这个默认值。手机上从 0.1.20 起，网页版和桌面版从 0.1.23 起
经由运行时（`nanomuse/avatar/studio.py`），形象工作室可以在聊天里按一句描述把新形象画出来：

1. **开口。** 在聊天里说：「换个形象：一只戴圆眼镜的橘猫」、"new avatar: a robot owl"、
   "change your avatar to a small fox with a scarf"。或者走工作室页面（资料面板里形象上的那支笔
   → 「形象工坊…」，或者「设置」里的工作室磁贴），那是手机的页面：顶部是现在的脸和它是什么、一段
   描述、七个风格标签、「画四张」，然后走完下面这个列表剩下的步骤，只是聊天里没有卡片（进度通过
   socket 以 `{"kind": "studio", "current"}` 送来）。这一步不运行智能体。
2. **配置你的图像服务商。** 先在「模型」里添加图像服务商和 API key。nanoMuse Cloud
   不再由项目方付费提供生图或生视频；工作室把生成文件留在设备上，并使用你选定的服务商。
   Android、iPhone、网页和桌面端的描述框上方都有四张形象灵感卡。点一张只会填入描述和风格；
   直到你让自己的服务商作画并选中结果，它都不会替换现在的脸。四套示例是「苔邮使」「潮汐巧匠」
   「暮光蛾」和「铜果」；五状态图片在 `assets/avatar-presets/`，其中的 `source.json`
   记录模型、日期、非敏感 prompt 和原创/许可证说明。名称、描述和风格提示跟随应用语言；共享资产
   只用稳定 id，不把英文当成固定界面文案。
3. **四张里挑一张。** 同一个主体画四次（经典配色、浅一些、深一些加一件小配饰、一个俏皮的版本），
   工作室的 3D 玩偶风格，全身，白底。点一张，或者说是哪张（「第二个」、"the first one"、"top right"）；
   「再画四张」再出四张。
4. **各个姿势。** 选中的那张就是待命的静态图；在它上面做四次编辑，得到其余几个状态（戴着耳机在
   笔记本前干活、抱着水晶球等你、抱着星星开心、带着一滴汗说抱歉），和小龙那套一样。它们落在工作区的
   `avatar/<face>/<mood>.webp` 下；资料里的 `avatar` 变成这张脸的 id；账号下的每个应用都会显示它
   （通过 `/api/files/avatar/<face>/<mood>.webp`）。画不出来的姿势就用待命那张代替。

图片从哪来：对话模型的主机和 key。中继会说 OpenAI 的 images API（`/v1/images/generations`、
`/v1/images/edits`），任何能画图的 OpenAI 兼容服务商也一样；阿里云百炼自己的主机两者都没有，于是
用同一把 key 调它原生的多模态接口（默认 qwen-image-3.0）。由哪个模型来画，是 `config.toml` 里的
`[image]` 一段（`[llm] image_model` 仍然有效）、网页控制台「连接」页的「生成图片」一行，或手机和桌面版的
设置 → 模型；留空就是「自动」：对话模型所在的服务商能画就用它（百炼上是 qwen-image-3.0），否则用你配置的
另一家图像服务商，否则没有，这时聊天会直说，而不是硬试。

Android 现在也可使用通过 API key 添加的 Google Gemini 服务商来生成和编辑形象。在「设置 → 模型」
里选择它的图像模型，名称含 `nano-banana` 的模型也能被识别。应用调用 Gemini 原生的
`generateContent` 接口，请求文字和图片输出；制作其他姿势时会带上选中的图片。Imagen 使用另一套
接口，因此不会列入这个原生 Gemini 图像模型列表。OpenAI 兼容服务商继续走原有的图片接口。

静态图穿上之后，只要接口有视频模型，工作室就会像手机上那样，从这几张图做出四段短视频（待命、
干活中、等你回复、搞定；动作是固定的那几套）：使用你配置的服务商，例如百炼上的通义万相，走异步
视频 API（上传、建任务、轮询、拿 MP4）；`[video]` 一节（或旧的 `[llm] video_model`，见 [configuration.md](configuration.md#image-and-video)）覆盖模型的选择，`[llm] video_base_url`
在那个 API 的主机不是对话模型的主机时指明它（像展示站网关这样的中转主机会替它的运行时设好）。它们落在
`avatar/<face>/<mood>.mp4`；短视频生成期间卡片显示 `animating` 阶段，费用卡片把它们算在内，失败的
一段保留它的静态图。没有视频 API 的 OpenAI 兼容服务商只给静态图。网页版和桌面版在 44 px 及以上播放
短视频（小龙自己的四段随网页版一起发布）；在列表和选择器里、在 `prefers-reduced-motion` 下，或者
某段短视频缺失时，低于这个尺寸的地方只显示静态图。

这些灵感资产在规范的 `source.json` 中明确标为 AI 生成。它们来自经认证、按量计费的百炼模型推理
HTTP API，不是百炼控制台体验：`qwen-image-3.0-pro` 通过原生同步多模态端点生成 20 张图片。
清单记录端点类型、维护者证明、成功数量、prompt、每个文件的 SHA-256 以及官方 API 和条款链接，
但不记录凭据、账号、私有主机、请求 id 或签名结果 URL。体验功能与 API 输出的条款区别，以及 API
调用者把其可能持有的权利按 GPL-3.0-or-later 贡献给项目的说明也在清单中；这是项目事实记录，
不是法律意见。

`GET /api/avatar` 告诉你这里能不能画脸（以及用哪个短视频模型）、哪个会话正在进行、资料现在穿着
哪张脸和它是什么：描述、风格和模型，在姿势落地时写进 `avatar/<face>/face.json`；`POST
/api/avatar/begin|start|choose|cancel` 驱动一个会话（聊天卡片和工作室页面都用它们），`POST
/api/avatar/moods` 把正在穿的脸的姿势和短视频重画一遍。结束的会话的候选图一天后清掉；脸留在工作区里，
只要资料，或者你，还想要。

有 nanoMuse Cloud 账号时，这张脸跟着你到每一台设备（[docs/cloud.md](cloud.md)）：静态图上传到中继
一次，其他设备从 `avatar/sync-<hash>/` 穿上它，描述和风格写在它们各自的 `face.json` 里；如果账号上
的图片正是某台设备已经在穿的，那台设备保留自己画的那张脸，连短视频一起。

## 你自己的视频 {#your-own-clip}

一段你自己的短视频可以顶替那几段短视频。手机上，在资料页形象上的那支笔下面选（「你自己的视频…」），
或者在形象工作室的「你自己的视频」一节里选；桌面版在形象工作室或资料抽屉里选。只要形象在动的地方，
这段视频就静音循环播放：待命状态用它，其他状态也用它，因为只有这一段。需要静态图的地方（视频第一帧
出现之前垫在下面的那张、分享卡片、磁贴）仍用工作室画的那套静态图；没有工作室形象时，视频的第一帧就是
静态图。改动之前先预览：视频在形象自己的圆框里播放，下面是「使用」和「取消」；「默认形象」移除这段
视频，工作室的脸或小龙重新出现。

限制在每台设备上相同（[every-device.md](every-device.md)）：MP4 或 MOV，最长 15 秒、最大 30 MB，
H.264 视频；设备能播的话也收 HEVC（iOS 一直可以；桌面版要系统带解码器，预览放不出来的会在那里被拒绝；
Android 目前只收 H.264）。更长、更大或别的格式会被拒绝，并用一句话说明限制；不裁剪、不转码，声音永远不播。

视频留在选择它的那台设备上。它不上传到 nanoMuse Cloud，也不同步到你的其他设备，这一点和工作室形象的
静态图不同；每台设备各选各的。Android 上它在 `minis-global/nanomuse/avatar/own-clip.mp4`，第一帧
在旁边的 `own-clip.png`，和当前登录账号的其他文件归在一起；iOS 上在应用的
`Application Support/nanomuse/avatar/own-clip.mp4`；桌面版在 `$DSH_HOME/nanomuse/avatar/own-clip.mp4`。
换一张工作室的脸或者退回内置形象，它都还在。

Android 上这个目录在 App 自己的存储里，文件管理器和 shell 都打不开，所以工作台的菜单里有「保存到相册」：
把底图、各个状态的静态图、上一次生成的四张候选图、动起来的状态视频和你自己的视频复制到
`Pictures/nanoMuse/avatar` 和 `Movies/nanoMuse/avatar`，每一批按保存的那一分钟命名，完成后告诉你存了几张图、
几段视频。文件只到这台手机的相册，不去别处；清掉 App 数据或换手机之前，靠它把形象和视频留下来。
（[#664](https://github.com/nano-muse/nanoMuse/issues/664)）
