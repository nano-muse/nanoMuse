# 桌面窗口逐屏说明 {#桌面版的窗口-一屏一屏看}

> 本页说明基于 DeepSeek Harness 的 nanoMuse 桌面版界面，包括主窗口、首次引导、资料与形象、电脑操作、设置、各功能页面及底部菜单。设计计划和实施记录见 [harness.md](harness.md)。

桌面应用由 **DeepSeek Harness 和 `dsh-nanomuse` 插件包**组成，见 [harness.md](harness.md)。Harness 是组织智能体运行的框架，dsh 提供智能体循环、工具和完整的网页应用，也预留了插件可以替换的界面位置。nanoMuse 插件包通过这些位置采用与手机相近的布局，将 harness 自有控件放在「高级」，并加入账号功能，使各设备使用同一个智能体，支持 Reach 跨设备操作及开放的模型接入。

在聊天输入框中，按 **Shift+Enter** 换行，按 **Enter** 发送。**高级 → Harness** 中的回车设置用于选择智能体忙碌时如何投递消息，不会改变换行快捷键。

## 主窗口 {#the-window}

窗口最左边是窄图标侧栏，旁边是聊天列表，中间是对话。智能体形象、名字和实时状态固定在对话上方，输入框位于底部。任务运行时，圆形发送按钮会变为方形停止按钮。应用支持浅色、深色和跟随系统，界面各区域使用相近的纯色，不增加装饰。这些布局来自 dsh 的 `sidebar` 插槽和对稳定 DOM 标记的样式调整，例如 `data-composer-card`、`data-chat-flow-kind`、`data-approval-key`。DOM 是网页的元素结构。

- **图标侧栏**从上到下是聊天、搜索、动态、点子、目标、资源库、设备，底部留出空隙后是菜单。智能体工作时聊天图标有圆点，有未读帖子时动态图标有圆点。日程和 harness 的其他面板在底部菜单中。侧栏不放形象，形象位于对话顶部和资料面板。macOS 没有标题栏，窗口控制按钮位于侧栏顶部的空白拖动区，全屏时去掉这段留白。Windows 同样无边框，通过 `titleBarOverlay` 在右上绘制随主题变色的系统按钮；Linux 则保留窗口管理器标题栏，因为没有通用覆盖方案。Windows 的动态、目标、资源库及文件查看器、文档编辑器、资料面板、首次引导、插件、日程和右侧停靠栏，会在顶栏右侧为系统按钮留空，将自身操作放到其左侧。右上窄栏中的任务详情则把标签移到系统按钮下方。全屏和顶栏原本较低的分屏不额外留空。
- **聊天列表**顶部有「搜索」及包含归档聊天的「···」菜单。一个「主要聊天」始终置顶，可以是首个会话，也可通过「设为主要聊天」指定。「旁聊」旁有「+」，列出其余会话，置顶项优先。每行的「···」可设为主要聊天、置顶、直接重命名、归档。空会话称为「新聊天」，圆点表示运行中，另一个标记表示等待你回答。列表可折叠，只保留图标侧栏。登录后只显示当前账号的对话：同步来的聊天会记住来源账号，其他账号的内容仍在本机，但不出现在列表和搜索中，也不上传到当前账号，直到原账号重新登录才显示。切换账号会从头拉取同步，未登录时显示所有本地内容。
- **对话顶部**使用 `conversation.header.leading` 插槽，将形象和名字固定在中央。状态标签显示「已连接」「未登录」「思考中…」「手 · 第 N 步 · 当前操作」「Reach · 第 N 步 · 在 Laptop B 上：…」或「等你回复」，运行时旁边有「停止」。工作和等待回答时，状态标签会带颜色。点击形象打开资料面板。右上方在登录后显示「邀请」，之后是 harness 右侧栏开关。harness 原标题行、「对话」「Trace」标签及会话操作隐藏，重命名、置顶、归档改在聊天行完成。
- **对话气泡**沿用手机的单色布局。用户消息在右，浅色主题黑底白字，深色主题白底黑字；助手消息在左，用与背景略有区别的大圆角灰色气泡。时间和单条消息操作在悬停时显示，用户气泡内的链接保持文字颜色并加下划线。顶部使用渐隐遮罩而不是独立横栏，消息从形象下面滚过并逐渐隐入背景，没有底部分隔线。空聊天没有欢迎语、工作区或预设标签，底部输入框在需要工作区时打开选择器。
- **输入框**是一个圆角长条，包含添加附件的「+」、消息输入区和发送圆钮，运行时为停止方块。发送按钮和回到最新消息的圆钮使用与用户气泡相同的底色，图标用相反颜色。已有对话时，即使 harness 底部停靠区隐藏，输入框与窗口底边仍保留原来的间隔。紧凑模型选择器放在输入框旁；模型支持调整推理强度时，只显示文档确认支持的档位，选择仅作用于当前聊天。权限模式和计划开关默认隐藏。四种用途的默认模型在设置 → 模型，dsh 自己的模型页在「高级」，默认权限模式在「通用」。开启通用中的「显示 DeepSeek Harness 原生控件」后，隐藏控件会重新出现。插件中启用 harness 语音输入后才显示麦克风，设置 → 听写提供说明。
- **主题颜色**覆盖 harness 默认配色。浅色主题使用 `#f9f9f9` 区域背景、纯白对话背景、`#000000` 用户气泡、`#f2f2f7` 助手气泡；深色主题使用 `#171717` 背景、`#ffffff` 用户气泡、`#242424` 助手气泡、`#2b2b2b` 输入字段。强调色来自账号形象的颜色，因此手机设置的颜色也会用于桌面指示灯和链接。外壳与页面使用相同底色，深色模式调整窗口大小时不会闪白。

## 首次运行 {#the-first-run}

首次引导沿用手机页面，Android 实现为 `FirstRunSetup`，在 harness 的 `settings.onboarding` 插槽内全窗口显示。插件接管默认步骤的 id，因此新用户先看到 nanoMuse，而不是输入 DeepSeek key 的要求。Host（管理插件、模型和会话的后台进程）将状态保存到 `$DSH_HOME/nanomuse/firstrun.json`，代码为 `src/firstrun.ts`，记录是否点击「开始」、是否看过权限页及模型来源。这样，全新安装不会跳过引导，完成后也不会重复显示。

1. **欢迎**。显示应用标志、「欢迎使用 nanoMuse」、对话、手、Reach 三项功能及社区声明。形象会在最后的认识页面出现，与首次对话衔接。蓝色「登录」按钮下提供「改用自己的 API key」，可不登录直接进入模型页，以后再登录。未保存 key 就点「先跳过」会返回欢迎。API key 是调用模型服务的密钥。登录使用与手机相同的手机号或邮箱流程，并说明只有中国大陆手机号能收短信，其他用户使用邮箱。验证码输入第六位时自动验证，「试试其他方式」可改用密码。接口为 `/v1/auth/code`、`/v1/auth/verify`、`/v1/auth/login`。
2. **设置密码**。仅新账号显示，「以后再说」可跳过。
3. **选择回答来源**。使用 Cloud 账号模型或自己的 key。
4. **选择模型，仅自有 key**。服务商来自 `assets/providers.json`，与手机及网页版相同。所在地区的服务商优先，中国大陆为阿里云百炼，一把 key 可覆盖对话、手、图片和视频；其他地区先 OpenRouter，再 OpenAI。每行说明支持用途，「去拿 key」打开厂商页面，「添加 key」直接保存到凭据库的 `NANOMUSE_KEY_<PROVIDER>`，`cloud.json` 只保存引用名称。OpenAI 下方提供「用 ChatGPT 登录」，通过 OpenAI 页面登录 Plus、Pro 或 Team 套餐，只支持对话和屏幕操作，不含图片和视频，并说明 OpenAI 条款涵盖自家 Codex，其他应用曾被停止这种访问。「更多途径」展开其余服务商、本机 Ollama、LM Studio、vLLM，以及手动填写的 OpenAI 兼容接口。保存 key 或完成登录前按钮为「先跳过」，之后变为「继续」。
5. **允许 nanoMuse 使用电脑，仅 macOS**。辅助功能和录屏各有「允许」，通过桌面外壳申请。程序会轮询，并在窗口聚焦或页面重新可见时检查；所有权限显示都使用 `permissions.ts` 的同一逻辑。成功后变成绿勾，点过允许后按钮改为「打开系统设置」。需要开启的是负责截图和鼠标的 **nanoMuse Computer Use** 辅助程序，两行都标明名称，授权后它会自行重启，主应用不用重启，见 [desktop.md](desktop.md#macos-permissions)。不带辅助程序的旧构建，即 0.1.38 之前，权限属于主应用。外壳会先尝试截图，使 nanoMuse 出现在系统列表；运行中授权后，系统只对新进程生效，应用会提示「立即重启」，通过桥接调用 `relaunch`。页面的「试一下」可测试截图和鼠标移动，运行时行还会显示可执行文件及 Host 记录的上次启动失败原因。截图全黑会另给提示和重启按钮。Linux、Windows 跳过此页。
6. **认识 <名字>**。显示形象和「开始」。

点击「开始」后，主要聊天绑定到智能体自己的 `~/nanoMuse` 文件夹，该目录注册为工作区，输入框即可使用。这里开始与手机 `FirstConversation` 相同的首次对话：应用先显示三句预设文字，不消耗 token，也不写入模型历史，再问该如何称呼你。Token 是模型计算文本长度的单位。

接着由模型对话，并在回复末尾输出 `nanomuse-naming` 数据块，报告对你的称呼、推荐名字和最终名字。聊天将建议显示为 `NamingCard` 起名卡片，可以点击或输入名字。流程只根据这个数据块推进；没有数据块表示用户谈了其他话题，模型先帮助处理，再引导回来。智能体确定名字后，引导完成，生成第一天的动态，并设置每日例程。

帮助与支持 → 再看一遍首次引导可主动重开这些页面，但不会重复首次对话。

## 资料与形象 {#the-profile-and-the-face}

点击对话顶部的形象，会在聊天右侧打开 310 px 的智能体资料页，沿用手机 `AgentProfileScreen`，聊天会缩窄为其让位，× 或 Escape 关闭。页面显示 86 px 形象及铅笔菜单、名字、在线或未登录或离线状态，以及当前操作。分享按钮生成带形象和名字的卡片，可保存为图片或复制。

铅笔菜单中的「更换虚拟形象」会将「把虚拟形象改成…」放入输入框，使用下文聊天流程；还可「编辑名称」或进入「形象工作室…」，在小龙、彩色背景 emoji、生成形象之间选择。登录时选择会写入账号并同步各设备。

资料页有四个标签：

- **活动**：显示会话及 hub（设备互联）的通知，分「今天」「更早」。
- **审批**：显示每个应用的长期允许授权，注明仅限某聊天或任务的范围，并可「撤回」。「管理权限」进入设置 → 电脑操作。下方还显示你在卡片中允许和拒绝的记录与时间，只保存在本机。
- **每日**：显示例程，「管理每日任务」打开 harness 日程面板。
- **SOUL 与记忆**：逐行显示智能体记住的事，可以输入添加、点 × 忘记，或通过「导入记忆」粘贴其他助手的记录，每行一条。账号有描述时也显示智能体描述。你告诉它下次应记住的信息时，它会调用 `remember` 保存，每次聊天的提示词都会包含列表，存储为本机 `rooms.json`。

从其他助手迁入时，先看[迁移指南](migration.md)，了解记忆导入限额，以及文档和连接器的处理方式。

「更换形象」中可选小龙、带背景色的 emoji 或「画一个」。工作室要求描述角色、选择风格，默认 3D 玩偶，再选自己的图像服务商和 key。点击「画四张」，四个候选按 2×2 显示，编号为选项 1–4。点击「就这个」，会以所选图片生成干活中、等你回复、搞定、出了点问题等其他状态，再让账号所有设备使用新形象。

图片直接交给所选自有服务商，也可使用明确提供媒体能力的自建中继。浏览器将各静态图处理为 512 px 正方形 WebP，Host 通过带 `face` 映射的 `PUT /v1/me/profile` 写入账号，再取回到 `faces/<id>/`。未登录时，使用已有生成文件保存在 `faces/<id>/`，只在本机应用形象，不再重复生成。之后登录会使用账号形象覆盖本地选择，与未登录时选 emoji 相同。提示词沿用运行时，因此手机与桌面的生成风格一致。

**在聊天中更换形象**使用手机相同的 `AvatarFlow`。发送前，`src/avatar-flow.ts` 的同一组正则表达式会识别 "change your avatar to an orange cat with a scarf"、「把你的形象换成一只橘猫」、"become a robot" 等请求。输入框上方卡片说明生成服务商，点「开始画」后按 2×2 显示编号候选。你可点选，或说「第二个」、"the second one"、"regenerate"。随后「正在完成形象」生成其他状态，所有设备换用新形象，「分享形象」提供分享卡片。

完成后，Host 写入与手机相同的记忆行 `- <日期>：用户把我的虚拟形象换成了"…"`，要求智能体用一句话说明，并输出 `nanomuse-avatar` 代码围栏块，也就是用指定标签标记的结构化数据。聊天将其显示为带新形象的小卡片。智能体仍可用 `draw_new_look` 打开工作室，提出其他形象建议。

**形象动画**按状态播放。小龙的待命、干活中、等你回复、搞定四种动画来自手机短片 `assets/dragon-<state>.mp4`，在顶部、资料页、舞台光标标记等不小于 44 px 的位置静音循环，静态图作封面。较小位置、列表或系统减少动态效果时，只显示静态图。

生成形象也可用自己的百炼 key，通过 `wan2.2-i2v-flash` 制作四段各 4 秒的同类状态视频，或使用明确启用旧媒体代理的自建中继。实现位于 `src/video.ts`、`src/motion.ts`，提示词与手机相同。本机文件在 `avatar/motion/`，通过 `/face/<id>/<state>.webp|mp4` 提供，在顶部、侧栏和胶囊播放。登录后，中继 0.29 会让视频随形象同步：本机生成的视频作为文件上传，引用写入 profile 的 `clips`；其他设备已有的视频直接下载，不重复生成，因此同一账号的同一形象只需制作一次动画。

设置 → 图像与视频中提供默认开启的「换形象后自动生成动作」、「现在生成动作 / 重新生成」及所用模型，工作室费用估算包含视频。视频尚未完成或关闭该设置时，生成形象和 emoji 使用 CSS 动画：待命时缓慢缩放，工作时摇摆，等你回复时轻跳。

## 电脑操作 {#computer-use}

手通过 MCP（连接工具的统一协议）提供运行时的 `computer_screen`、`computer_act`。模型看到的是自己请求的截图，状态条显示「手 · 第 N 步 · 点击保存」等进度。0.1.34 至 0.1.39 曾在窗口内显示调暗的实时屏幕舞台；0.1.40 改为下文可回看的轨迹，因为跟随操作的画中画会增加动态内容，又不能事后回看。

harness 的审批卡片使用 nanoMuse 权限卡片样式：盾牌、标题、详情，蓝色「允许一次」在前，灰色「拒绝」在后。哨兵（Sentinel，检查操作风险的组件）的理由显示在标题中，见 [sentinel.md](sentinel.md)，每次回答记入资料页的审批标签。

屏幕操作卡片上方还会显示「本对话中始终允许」「在 <应用> 里始终允许」，因为 harness 卡片内放不下，应用名称取窗口标题第一部分。nanoMuse 窗口不在前台时，外壳的始终置顶胶囊也显示相同问题，以及允许一次、聊天内始终允许、应用内始终允许、拒绝。Host 的 `ApprovalDesk` 在 `approval/request` 处理链中排第一，接收这些回答。

「在 <应用> 里始终允许」保存 `computer_app:<app>`，此后在该应用中手的工具不再询问，直到你在资料页或设置 → 电脑操作 → 已始终允许撤回。「本对话中始终允许」还保存 session id 和标题，只对该聊天生效，定时任务也在同一聊天运行，因此能使用此授权。列表注明「仅对话「…」」。

当轮次由定时任务提醒启动时，卡片和胶囊会改为「此定时任务中始终允许」，额外保存任务 id、标题，只对该任务发起的轮次生效；有人在该轮次中发消息后，就不再适用。一轮同时运行两个任务，需要各自授权。列表注明「仅定时任务「…」」，任务删除后会标记。

这些授权限制的是应用，不限制收件人或文字。因此，在被授权聊天中，手可以在该应用向任何人发送任何内容。设置 → 电脑操作展示 macOS 两项权限、「允许」「打开系统设置」、保持屏幕常亮及风险说明。首次使用会按先辅助功能、后录屏的顺序申请，并说明原因。此处早期实现从 0.1.36 起由 nanoMuse Desktop 二进制截图、点击，内置 `nanomuse` 仅在脱离外壳运行时需自行授权；辅助程序的现行权限方式见上面的首次引导说明。会话运行期间，常亮选项由外壳的防休眠机制执行。页面还说明发送、付款或删除操作会先询问。

**暂停并交给用户操作**。需要输入密码、完成人机验证或作出不应代替用户的选择时，智能体调用 `computer_act`，传入 `action: "hand_over"` 和 `reason`。Host 创建暂停状态，契约 C1 为 `{type:"hold", tool:"computer", status:"on", by:"agent", reason}`。聊天轨迹卡片和窗口外胶囊显示「该你了 · <原因> · 好了」，胶囊和光晕变为琥珀色。工具最多等待十分钟，直到你点击「好了」。

你也可在轨迹卡片或胶囊点「我来接手」，通过 `POST /nanomuse/cloud/holds` 主动暂停。智能体会在下一次手的调用前等待，让你使用鼠标，点「好了」继续。问题仍保持「打开」状态，方形停止按钮仍用于取消整轮任务。

**操作器**负责实际截图和输入，代码为 `src/operator.ts`，基于 `@computer-use/nut-js` 移植 UI-TARS-desktop 的 `NutJSOperator`。通常由 Electron `desktopCapturer` 按显示器尺寸截图，Mac 则通过 *nanoMuse Computer Use* 和 ScreenCaptureKit，见 [desktop.md](desktop.md#macos-permissions)。点击前指针直接移动到目标，停 100 ms 再点击，也支持拖动、滚动、非 ASCII 文本剪贴板输入及快捷键映射，Mac 的 `ctrl` 对应 ⌘。

运行时 `nanomuse mcp` 通过外壳每次启动的本机 HTTP 服务调用操作器，预设将 `NANOMUSE_OPERATOR_URL` / `NANOMUSE_OPERATOR_TOKEN` 传给 MCP 服务器。模型坐标以看到的图片像素为准，只换算一次为屏幕像素，因此显示缩放不会造成落点偏移，见 [gui.md](gui.md#hands-on-the-computer-the-picture-is-the-unit)。单独运行 `nanomuse`、没有外壳时，仍使用 `pyautogui` / `xdotool`。

**运行指示的动画节奏**。0.1.40 起，工作状态不再用沿边缘转圈、扫过表面或闪光表示。聊天旁圆点、顶部状态点、其他设备工作点、回复下的思考点、监听麦克风、光晕、胶囊圆环和条形指示、轨迹实时点，都按手机相同节奏明暗变化：2.4 s 变亮，2.4 s 变暗，使用 ease-in-out 缓动。卡片滑入、标记锁定、点击的两圈波纹等单次动画、形象状态和普通加载转圈仍保留。系统开启减少动态效果后，明暗变化改为常亮，标记弧线静止。

**光晕和动作标记**。手操作屏幕时，外壳用透明、点击穿透、始终置顶窗口覆盖整个显示器。这相当于 UI-TARS 的 ScreenMarker，或针对桌面绘制的手机 `HandsStage.kt`。屏幕四边显示明暗渐变的光晕，深度为短边 7%，外缘为 1.5 px 细线。工作时动作蓝，暂停时琥珀色。

实际动作位置显示标记：柔光、12 px 动作蓝圆环、旋转青色弧线、白芯中心点，以及深色圆角标签中的动作名称，靠右边时标签放左侧。标记在 220 ms 内由 1.8 倍缩小到目标位置。点击出现两圈波纹，拖动绘制蓝到青的虚线路径、箭头及终点环，并让圆环沿路径移动。打字、组合键、打开应用、等待等无明确落点的动作，在上次标记位置显示名称。动作结束 1.6 s 后淡出。

标记位置来自操作器自身相对显示器的坐标，因此与实际点击一致，不依赖客户端解析工具调用。使用运行时自身等其他后端时，以客户端坐标替代，不显示文字。光晕从本轮首次 `computer_screen` 或 `computer_act` 开始保持显示，模型在两步间思考时也不断开。Host 的 `hands.run` 指出哪个会话占用屏幕；过去只跟踪进行中的单次调用，会导致每两步间熄灭。现在轮次结束、点停止或五分钟无调用后，400 ms 消失。

光晕不能获取焦点或点击。光晕、胶囊及屏幕操作期间的 nanoMuse 主窗口均使用 `setContentProtection(true)`，不会出现在运行时截图中。Linux 内容保护无效，因此光晕和胶囊在截图瞬间隐藏。桌面没有手机的长按动作，所以没有长按圆环。手机形象只在胶囊内跟随手指，桌面曾于 0.1.34 至 0.1.39 跟随指针的形象也已移除。

**胶囊状态条**沿用手机 `HandsCapsule`，尺寸适合鼠标操作，放在可用工作区域顶部中央，宽度最多 420 px，背景为 82% 不透明度深色，带白细边。36 px 形象外围是动作蓝、紫、青三色环，与四条小竖线同步明暗变化。旁边显示「第 N 步」、查看屏幕、已点击保存、已输入 hello 等操作文字，模型思考下一步时保留上一步说明，并提供「我来接手」和红色「停止」。

手开始时胶囊用 320 ms 滑入，整次运行持续显示，但只有主窗口不在前台时可见；主窗口中的轨迹卡片提供相同内容。结束后 220 ms 消失。如果手要在胶囊下面点击或拖动，它先移到底部，下次再回顶部，避免遮挡操作。暂停时变为琥珀色并显示「该你了 · <原因> · 好了」。审批卡片悬在下方，提供「允许一次」「本对话中始终允许」，定时任务时改为「此定时任务中始终允许」，手的步骤还提供「在 <应用> 里始终允许」，以及「拒绝」。主窗口通过 IPC（进程间通信）发送 `nanomuse:overlay` 和 `{hands: {active, held, step, title, text, face, stop, take, x, y, kind}, cards}`，回答也经同一路径返回。

**轨迹**用于运行中和结束后回看手的操作。卡片位于本次运行最后一个工具调用下方，属于聊天内容，会随对话滚动。它显示步骤截图和动作标记：点击圆环与中心点，双击为两环；拖动虚线与箭头；滚动箭头；输入文字、组合键，或无落点动作中的应用名称标签。说明如「第 3 步 · 已点击保存 · Finder」，还有操作前智能体最后一条简短推理，卡片最多三行。

卡片包含缩略图带、「上一步」「下一步」，聚焦时可用 ←、→，Home、End 跳到首尾。「放大查看」打开包含完整文字的步骤面板，「复制这一步」复制当前步骤。运行中自动跟到最新一步，显示明暗变化圆点及「我来接手」「停止」；暂停时显示「该你了 · <原因>」和「好了」。图片按需加载，只有当前选中步骤使用全尺寸。

Host 通过 `src/trajectory.ts` 将轨迹保存在内存。一次运行从本轮首个手调用开始，到轮次结束或十分钟没有手操作为止。一步包括模型看到的截图、之后针对该图执行的动作，以及操作前最近的助手文字。`computer_screen` 返回截图，`computer_act` 返回操作后画面；`tools/execute` 中间件从 MCP 结果提取图片，并读取第一行的窗口标题和尺寸。

上限是**每次运行 40 步**、**合计 4 次运行**、图片总量 **64 MB**。超过步数从最早移除，并显示「最早的 N 步已不再保留」；图片超限也先移除最旧图片，保留步骤文字并注明图片不在。轨迹不写磁盘，重启即清空。网页组件通过 `GET /nanomuse/cloud/trajectory?session=<id>` 获取 `{rev, runs: [{id, sessionId, source, device, startedAt, endedAt, firstCall, lastCall, dropped, steps: [{i, seq, at, width, height, title, action, words, callId}]}]}`，不含图片字节；用 `GET /nanomuse/cloud/stage/frame?seq=N` 获取图片，该图片不可变并缓存一小时。实时状态的 `trajectory: {rev, sessions}` 提示何时更新。

通过 Reach 的 `device_screen` 查看手机时，轨迹标为带手机名字的设备运行。这是从桌面查看手机手工作时的画面，见 [gui.md](gui.md)。

## 技能可用性 {#skill-availability}

「设置 → 技能」列出当前对话的技能，包括已禁用的技能。你可以按名称、说明搜索，也可以查看纯文本形式的来源、提供方和指令文件路径。页面不会编辑或删除技能文件，因此其他使用 `~/.agents/skills` 的工具不受影响。

选择「当前工作区」只修改页面显示的工作区；选择「所有工作区」则对整个 nanoMuse 生效。技能默认启用，全局禁用优先：如需调整某个被全局禁用的技能，请先在「所有工作区」中启用它。全局启用不会清除已有的工作区禁用设置。未选定工作区时只能调整全局设置；全局列表可能不包含部分对话独有的技能，但其中的设置仍会按名称作用于整个 nanoMuse。工作区路径会解析符号链接，并按文件系统技能发现规则采用最近的 Git 项目根目录；同一项目下的子目录共用设置。

设置按最终技能名称生效，也包括来自不同位置的同名技能。禁用后，它仍可在此管理页查看，但不会出现在智能体的技能目录中，也不能通过技能加载器加载。这些开关控制后续的技能发现和加载，不会删除共享文件或撤销工具权限；授权规则请在「设置 → 权限」中调整。此前已加载到对话中的指令仍保留在历史记录中。工作区控制要求当前对话已建立受支持的智能体技能服务。尚未运行的会话，或使用独立且不受支持技能服务的自定义预设，会显示为只读；仅打开对话并不代表已支持。此时仍可切到「所有工作区」管理全局设置。服务端会核对工作区修改对应的对话及其规范路径。无法读取设置时，页面会停止修改并说明原因。目录未完整加载时也会显示提示，避免把未列出的技能误当成已禁用。

## 设置 {#settings}

设置使用带侧栏的对话框，来自 `sidebar.settings` 插槽，插件包会关闭 harness 默认的通用插件。在设置页内点击链接前往另一页时，目标页顶部会显示以来源页命名的返回入口。例如模型页「添加服务商」打开账号中的接入方式，通用页账号卡片打开账号，文件页「沙箱」打开智能体。直接点侧栏则重新开始导航。

- **通用**：账号卡片显示脱敏标识或「登录」，点击进入账号；使用情况显示套餐和进度条，包括会员、不限量，或免费额度余量与升级。语言使用 harness 原有设置，外观支持浅色、深色、跟随系统，强调色随形象。有桌面外壳时，应用行为提供「开机启动」，Linux 使用 freedesktop 自启动项；「显示在菜单栏 / 系统托盘」，图标提供打开 nanoMuse、新聊天、退出；以及快速唤起，macOS 为 ⌥ Space，其他平台 Ctrl+Alt+Space。唤起时打开新聊天并聚焦输入框，前台再按则隐藏，设置保存在应用目录 `desktop.json`。快捷键区域显示快速唤起组合，「更改」记录下一个按键组合，Esc 取消，「恢复默认」还原平台默认，被其他应用占用会说明，并提供键盘参考。「简介」显示 nanoMuse 基于 DeepSeek Harness、许可证，以及始终可见的两行版本：当前 nanoMuse Desktop `<app>` 与 harness `<bundle>`，以及最新版本、已安装最新、可更新或检查失败点击重试。每天先检查 `nanomuse.cn/dl/index.json`，再检查 GitHub releases。开发者开关「显示 DeepSeek Harness 原生控件」会显示模式和工作区浏览器，以后者替代聊天列；紧凑模型和推理控件本来就在输入框旁。权限预设、字号、链接打开方式、回车发送、性能、会话日志等原生设置位于高级 → Harness。
- **模型**：0.1.41 起紧跟通用，四行分别为「对话」，与你交谈；「操作屏幕」，需要识图模型；「生成图片」，生成形象肖像和所需图片；「生成视频」，制作形象短片。每行都有显示 `<provider> · <model>` 的选择器。登录后，仅中继实时菜单支持的用途才先列 nanoMuse Cloud，并标记推荐，随后按自有服务商分组，只显示支持该用途的模型。更换对话模型说明从新聊天生效；更换手的模型由插件重启 `nanomuse mcp`，下一步即可使用，不需重启应用。手仅支持 OpenAI 格式，因此 Anthropic 或原生 Gemini key 会在下方说明，不列入选择器。没有可用模型时，说明需要哪些服务商，例如图片需要百炼、智谱、SiliconFlow，并提供「添加服务商」。页尾同样提供入口，打开账号接入方式。未选择时，优先用自有对话服务商的对应用途默认模型，其次用已登录且实时支持该功能的 nanoMuse Cloud，最后用第一家支持的自有服务商。托管 Cloud 只有对话与屏幕操作，没有媒体生成。
- **账号，位于高级**：显示登录或脱敏标识、额度、形象、「打开设备页」，以及当前对话和手所用模型的设置 → 模型链接。账号与自有 key 共享「可用的途径」区域：登录时账号在前，并按中继模型菜单说明能力，其后按首次引导分组排列所在地区服务商、ChatGPT 登录、其他服务商、本地服务器、自定义接口，其他服务商按能力覆盖排序。每行说明用途，支持直接添加、更换 key、打开厂商 key 页面或「移除」。移除会删除凭据及指向它的对话或手的选择。自定义接口每个独立一行，见 #294，名称在上，主机在下，「改名」与「换 key」「移除」并列。「添加接口」创建另一条，使用独立的 `NANOMUSE_KEY_CUSTOM`、`NANOMUSE_KEY_CUSTOM_2` 等，不改其他接口，每条在模型选择器中自成一组；旧接口保留为首条。ChatGPT 行调用内置运行时登录，「登录」打开 OpenAI 页面，等待时提供「取消」「打开登录页面」，完成后显示例如已登录 ChatGPT Plus 并提供「退出登录」。它只支持对话与手，不含图片视频，下方保留条款说明。没有运行时时该行禁用并解释。已保存登录及本地桥接在重启后恢复。账号未登录时，这一区域仍位于登录表单下，可直接管理 key。保存 key 后卡片询问「用它来做什么」，提示选择负责的功能，其他模型保持原样。支持的对话、屏幕、图片、视频各有默认开启的开关，并显示将使用的模型。「就这样」更新对应模型行，「暂不」不改，脚注说明可随时在设置 › 模型更改。
- **图像与视频**：与设置 → 模型的图片、视频共用两个选择器，列出自有服务商，以及明确声明媒体能力的自建中继，视频还可选关闭。自有 key 图片直接发往服务商：百炼使用原生图片 API，OpenRouter 使用其图片 API，OpenAI、智谱、SiliconFlow、火山引擎和 xAI 使用 OpenAI 格式。工作室不再显示账号费用估算，而说明由哪个服务商、模型生成，不计入 nanoMuse Cloud。Google key 只通过其 OpenAI 兼容层生成。没有服务覆盖媒体时，按地区说明可用服务商，并指向设置 → nanoMuse Cloud，文字与工作室相同；只有 ChatGPT 登录时，明确说明其不支持图片视频。下方提供「换形象后自动生成动作」「现在生成动作 / 重新生成」、四段各自状态及费用说明。自有 key 失败时要求修复或另选自有服务商，不通过托管 Cloud 重试。
- **高级中的模型、智能体**：保留 harness 原有页面。
- **连接器**：提供搜索、分类标签及服务目录。分类包括全部、内置、工作、沟通、文件、代码与部署、数据、设计与网站、支付、搜索与网页、基础设施等。已连接在前，各行在白底方块显示服务标志，来自 [simple-icons](https://simpleicons.org/)，许可证为 CC0，`scripts/brand-marks.mjs` 生成到 `src/client/brand-marks.ts`，没有标志时用字母，末尾提供「连接」。详情按服务器描述列出能力，每个工具独立开关，说明权限由预设控制，手和邮箱由哨兵控制，并链接厂商文档。「断开连接」需确认两次。目录分以下三类：
  - **内置**展示实际可用能力。「手：这台电脑」在运行时响应后显示可用，否则说明缺运行时、路径不存在，或实际启动错误。邮箱、日历、通讯录工具通过 `nanomuse mcp` 到达后显示已连接；还包括 Reach 其他设备、网页、文件、终端、各功能页面、日程。连接邮箱、日历或通讯录先显示知情同意页，说明智能体可获得什么、由谁决定、凭据放哪里，再显示带复制按钮的 `nanomuse vault set …`、`config.toml` 配置和重启步骤。此处不提供登录按钮，凭据由用户自己的保险库保管。
  - **服务**来自 `src/connectors-catalogue.ts`，共七十五个远程 MCP 服务器，包括 Notion、Linear、Atlassian、Asana、GitHub、GitLab、Sentry、Vercel、Cloudflare、Supabase、Stripe、PayPal、QuickBooks、Figma、Miro、Canva、Dropbox、Box、Hugging Face、DeepWiki 等，保存各自地址及认证方式。点击连接先向服务器 `initialize`。开放服务立即连接；支持 MCP 授权的服务在系统浏览器打开登录，流程包括受保护资源与授权服务器元数据、RFC 7591 动态客户端注册、PKCE 授权码校验、RFC 8707 的 `resource`、本机 `127.0.0.1:38417/oauth/callback` 回调和到期前刷新。等待页可再次打开、重试、重新开始，最后一项用于服务器丢失注册时重新注册。需要 key 的服务会弹输入页，并指明申请位置。

    GitHub、Slack、Discord、HubSpot、Render、Bitrise、PagerDuty、Box 等不接受动态注册的授权服务器，在目录标为 `clientIdRequired`，运行时发现同类地址也采用专门表单。你需在所链接厂商开发者页创建 OAuth 应用，填入页面显示且可复制的回调地址，再粘贴 client id 和可选 secret。OAuth 是允许应用代表你访问服务、无需直接提供账号密码的授权机制。client id 会作为注册信息保存，下次不再询问。

    搜索输入两字符后还会查询公开 MCP Registry `registry.modelcontextprotocol.io`。「按地址连接」接受任意 Streamable HTTP URL，即可持续传输 MCP 消息的 HTTP 接口，「更多选项」可填 key 或预注册 OAuth 客户端。凭据只在本机 `$DSH_HOME/nanomuse/connectors.json`，不传给模型。智能体的 `dsh-mcp-client` 连接本机代理 `/c/<id>/mcp`，由秘密请求头保护。代理添加并刷新 token 或 key，过滤 `tools/list` 只显示启用工具，并拒绝调用停用的 `tools/call`。工具名为 `mcp__<service>__<tool>`，预设的 `nanomuse-connectors-tools` 为每个连接挂一个客户端，连接、切换、断开均随页面更新，无需重启。刷新被拒绝会显示需要登录和「重新登录」，key 可直接更换。
  - **预设**列出手动写入智能体预设的 `@deepseek-ai/dsh-mcp-client` 行，此页只读，「添加连接器」打开预设。

  这里不提供逐动作权限下拉框，由权限预设和工具开关控制；Zapier、Heroku 等要求预先在厂商注册客户端的服务，也不提供直接登录，在目录以 key 或地址类型列出。
- **电脑操作**：macOS 系统权限、保持常亮、风险说明。
- **文件访问**：列出主目录、资源库、下载和 nanoMuse 自有文件夹，可在文件管理器打开，但此页不会授予权限。规则允许读取你点名的内容，写入遵循聊天权限预设。默认 `workspace-write`，除非智能体页另有设置，即聊天文件夹内自由写入，主要聊天为 `~/nanoMuse`；外部修改先拒绝，智能体申请且你允许一次后才执行。`read-only` 每次修改前都问，完全访问不询问，并说明沙箱隔离。macOS「完全磁盘访问权限」只关系到读取桌面、文稿、下载。用户主目录、下载和应用文件有意位于主要聊天工作区之外；从资源库或自有文件夹打开的聊天在相应目录写入。
- **听写**：使用 harness 本地 SenseVoice，在插件启用后，发送旁出现麦克风，音频留本机。窗口只向页面授予麦克风，不授予摄像头或其他权限。页面说明 macOS 麦克风授权及如何在输入框使用系统听写。
- **设备**：本机名称、允许手机在本机操作的远程控制开关、账号其他设备、在线圆点及「移除」。
- **权限**：汇总智能体能使用的电脑操作、文件、麦克风、连接器和其他设备，含远程控制状态，每行打开相应设置页。还说明通过输入框上方标签切换的权限预设及最近审批。
- **钱包、安全存储、消息渠道的设计说明**：这些项目用于说明桌面版的边界。它不保存付款方式，也不在聊天完成购买，智能体在结账页停下，用量放在通用设置；说明本机保存登录、资料、功能页面及文档、形象的文件路径和「显示文件夹」，不保存系统钥匙串或用户密码；说明桌面、浏览器、已登录邀请链接和其他设备等入口，桌面版未连接第三方聊天软件。下面另述这三项并非实际提供的页面。
- **数据控制**：显示隐私说明和隐私政策。「在我的设备之间同步对话」为账号开关，并显示中继保存的聊天、消息数量和「删除已同步的对话」。其下「同时同步旁聊」为本机开关，默认关闭；关闭时旁聊留本机，开启时上传本机旁聊并接收其他设备旁聊，见 [every-device.md](every-device.md)。账号记录展示中继完整保存的轮数、自有 key 轮数、图片数和保留期限，中继 0.29 起支持，见 [cloud.md](cloud.md#the-record)。「帮助改进 nanoMuse 的 AI 模型」使用中继开关，显示加入训练集的轮数，统一「删除」同时清除记录及训练轮次，与其他客户端一致。1.0.7 起，本机账号请求携带 `X-NanoMuse-Device`、`X-NanoMuse-Conversation`，自有 key 完成的轮次也事后连同图片文件上传，实现为 `src/record.ts`，不上传 key 或 base URL。「在这台电脑上」提供导入记忆、下载智能体数据及重置。下载在「下载」生成 zip 并显示文件夹，包含无登录 token 的账号快照、资料形象、功能页面、记忆和 harness 原格式聊天；排除代理密码、链接及超过 64 MB 文件。重置清除记忆、功能页面数据和本地形象，退出账号，聊天保留。
- **帮助与支持**：文档、网站、讨论区、报告问题、版本。
- **法律信息**：许可证、Meta 商标声明、DeepSeek Harness 和 OpenMinis 致谢，以及各客户端共用的 `nanomuse.cn/privacy/` 隐私政策。
- **高级**：集中列出其他插件注册的页面，包括 harness 插件管理器、归档会话等，位于底部。
- 登录时底部提供**退出登录**，退出或重置会像全新安装一样返回欢迎页。

桌面版不实际提供钱包、安全存储、消息渠道这三个页面。Cloud 没有钱包，会员获得的是额度，见 [cloud.md](cloud.md#allowance)。nanoMuse 不为智能体保存用户密码，主动消息通过手机应用通知送达，而不是第三方聊天软件。

## 侧栏功能页：动态、点子、目标、资源库 {#the-rail-s-other-rooms-feed-ideas-goals-library}

这里将四个功能页称为「房间」。它们与聊天、搜索、设备一起位于图标侧栏，各自是 harness 布局的 `main` 主面板。打开时会切换主内容，聊天列仍留在原处。宿主服务 `nanomuse-rooms` 的实现为 `src/rooms.ts`，将数据保存在 `$DSH_HOME/nanomuse/rooms.json`，提供 `/nanomuse/rooms/*` 接口，并实时向网页组件发送变化。

- **动态**由智能体根据动态偏好、目标和资料，在隐藏会话中撰写。帖子包含标题、带链接的 Markdown 正文，来源页面有图片时也会附图，并提供 ♡ 和「讨论」，后者为该帖子打开旁聊。首次进入显示与手机相同的「关于动态」卡片，说明内容来源，并提供编辑偏好和知道了。空页说明每日例程的时间，例如每天 08:00 阅读关于你的记忆，并可「现在写一批」。第一天动态在首次对话结束后生成；每日例程在首次打开页面时建立，默认 08:00，可在调节入口下更改或关闭。图标圆点表示上次访问后有新帖子，智能体也可从任意聊天调用 `feed_post` 发帖。
- **点子**沿用手机 `assets/ideas.{en,zh}.json`，24 项分为出行、工作、生活、学习、家庭与关系、更多点子六类。每项有 emoji、第一人称介绍和细节。点开后说明将开始对话、创建 08:00 例程或创建目标。「发到聊天」只将文字放入输入框，由你补充；「创建例程」会在独立聊天按指定时间建立每日任务，并提示设置时间和细节；「开始这个目标」用点子文字启动目标聊天。试过的项目显示绿勾，⋯ 可隐藏。
- **目标**显示「● 追踪」列表，分类为健康、人际关系、金融、职业、兴趣、效率提升，包含智能体状态说明、报告过进度后出现的进度条及需要留意标记。创建目标 › 分类沿用手机流程，将类似「我想创建一个健康方面的目标」及目标整理提示发到当前聊天，当前忙碌时新建。智能体一次问一个问题，最多三个，了解做什么、为什么、期限和检查频率，再输出 `nanomuse-goal` 数据块。聊天显示目标已创建卡片，包含标题、原因、步骤、每天 09:00 或每 N 小时检查、在目标中查看。Host 创建目标，并以该聊天处理后续，使用 harness 日程插件安排检查，消息如该看看这个目标了、第一次。每次检查及进度发生变化的轮次末尾，会输出 `nanomuse-goal-update`，包含 `goal_id`、`progress`、`status` 的 on_track / attention / done、`note`。聊天显示带进度条和备注的更新卡片，目标状态、进度、时间线同步变化，也可通过 `goals_room_update` 更新。菜单的「改为直接写下目标…」支持用自己的描述创建，「问问进展」立即执行一次检查。
- **资源库**按全部、文档、网页分类，影音内容再分图片、视频、播客，底部是系统文件。提供选择、最近和卡片网格。「+ 创建…」先收集需求，再打开采用 workspace-write 预设的聊天，将文件写入 `~/nanoMuse/Library`，中文界面称为「构件」。文字提供查看器和 Markdown 编辑器，恢复 IDENTITY.md 或 SOUL.md 默认文本前会询问；图片和影音直接展示，其他格式提供打开或在文件夹显示。智能体以 `present` 交付的内容都会加入，`library_add` 则只登记文件，不交付。创建自己的文档无需模型：「创建」旁菜单可新建「空白文档」，在资源库建立空 `未命名.md` 并打开编辑器；也可「导入 Markdown 文件…」，将选择的 `.md`、`.markdown`、`.txt` 复制入目录并列入文档。重名加序号，超过 2 MB 或格式不符则列出跳过文件。其他格式需等待支持转换为 Markdown。

这些功能页需要可回答的模型，未登录时会说明。生成动态的聊天属于智能体后台工作，运行时由页面的 `batches` 标记，从聊天列表和搜索隐藏，解析完成后归档，以免占据用户列表。请求仅在该聊天显示「写今天的动态」一行通知，不冒充用户消息。1.0.4 及以前，批处理期间会出现在列表，并将提示词显示为用户气泡。智能体在任意聊天写出的 `nanomuse-feed` 数据块，也会按手机相同方式发布到动态，并显示「已发到动态」卡片。

定时任务在创建它的聊天里运行，由 harness 的日程插件投递提醒，聊天关着时会先恢复。`schedule_list_all` 让智能体查看当前账号可访问聊天中进行中的任务，并显示各自所在的聊天；已清空的聊天和已知属于其他账号的聊天不会列出。`schedule_delete_any` 删除任意聊天中的任务前会请求审批，拒绝后任务保留。智能体会被要求在创建任务前先查列表，帮助发现已有提醒；这不能保证并发创建时没有重复。

## 底部菜单 {#the-hamburger}

菜单提供设置及快捷键，新版本出现时设置和 ••• 按钮均显示圆点；「更新到 0.1.x」打开发布页；「关于 nanoMuse」显示 nanoMuse Desktop `<app>`、harness `<bundle>`、许可证及 GitHub、Releases、文档、Issues；另有键盘快捷键、日程和已安装的插件等 harness 面板、折叠或展开聊天列，以及「报告问题」。

在桌面外壳中报告问题，会将窗口截图存入下载目录，打开已填构建信息的 GitHub issue 页面，并提示应拖入哪个文件；浏览器环境只打开 issues。dsh 已有但主窗口隐藏的插件管理、面板列表、归档会话、开发者工具等，都从此菜单或设置 → 高级进入。

## 账号增加的功能 {#what-the-account-adds}

- **设备之间互通**。手机使用同一号码登录后，桌面状态行会计入该设备。Reach 允许双方互相发起任务，见 [hub.md](hub.md)。
- **模型与自有 key**。会员可用中继模型，也可用 DeepSeek key 或 harness 支持的任意 OpenAI 兼容服务商。设置 → 模型分对话、操作屏幕、生成图片、生成视频四行。对话依据中继 `/v1/models` 的 `for: ["chat"]` 和 `recommended_for` 标记，屏幕依据 `for: ["gui"]`。托管 Cloud 目前两者均推荐 `Qwen/Qwen3.6-27B-FP8`。DeepSeek 只有 id 包含 `v4.1`、`vision`、`ocr` 时才标为支持图片。手的模型保存在权限 0600 的 `$DSH_HOME/nanomuse/hands.json`，由插件 MCP 客户端通过环境交给 `nanomuse mcp`，变更时重启该进程。自有模型单轮失败时，登录用户可选「这次改用 nanoMuse Cloud」重发同一消息，轮次结束回原模型，设置页不改，不会自动切换。
- **查看其他设备的连接器**。本机发布到账号资料的只有服务、名称、自定义 MCP URL、认证方式、设备来源，遵循 C3，不包含 token 或 key，Host 拒绝名称疑似凭据的字段。手机和其他电脑可在「在你的其他设备上」看到并点击「连接」，本机也会列出它们的连接器。
- **按地区显示接入方式**。中文界面、手机号登录或中继账号位于中国大陆时，账号页先列百炼，再 OpenRouter；其他地区顺序相反，各有「去拿 key」。
- **更新检查**。Host 每天检查一次，也可在简介点检查更新，优先读取中国大陆可达且无限流的 `nanomuse.cn/dl/index.json`，无响应时再请求 GitHub releases API，比较版本。新版本会显示圆点、更新到 0.1.x 菜单项，以及简介中的本平台「下载」按钮。Linux 默认 `.deb`，当前为 AppImage 时选 AppImage。结果缓存一天，但始终与当前运行版本比较，安装期间更新后不会再提示安装同版本。两个来源均失败时只缓存一小时，之后自动再试；主动检查不受缓存限制。
- **开源组件**。插件包使用 GPL-3.0-or-later，harness 使用 MIT 并保留声明，没有闭源组件，「简介」会说明。
