# 隐私

本页说明 nanoMuse 手机 App、网页版、桌面版、dsh 插件及 nanoMuse Cloud 如何处理你的数据。涉及数据用途的选项，集中在 设置 → 数据控制 中。

## 本机保存的数据 {#everything-stays-on-your-device}

智能体在 App 内运行。手机上，它使用 App 私有存储中的 Linux 根文件系统，也就是运行 Linux 工具所需的目录和文件；电脑上，它使用你安装的运行时，即执行智能体和工具的后台程序。对话、记忆、智能体创建的文件、定时任务、技能和设置，都保存在这些位置，以及你自行挂载的文件夹中。App 不包含第三方分析统计，也不会自动向我们发送崩溃报告。登录账号后发给中继的请求记录和事件，见下文说明。nanoMuse 唯一的服务器是下文所述的可选中继，没有中继也可完整使用 App。

## 哪些数据会离开设备 {#what-leaves-the-device}

- **模型服务商**。 消息、附图和工具结果会发送到你配置的模型端点，即接收模型请求的服务地址，例如阿里云百炼、DeepSeek、OpenAI、OpenRouter，或你自己的 vLLM、Ollama。请求使用你填写的 API key（访问服务的密钥），数据处理遵循该服务商条款。key 只保存在本机。
- **登录后的 nanoMuse Cloud**。 欢迎页的「登录，免费开始」或 设置 → nanoMuse Cloud 使用手机号或邮箱加验证码注册。之后 App 将项目中继作为模型服务商。中继负责账号、设备通信及请求转发。每个账号免费获得 ¥10 模型额度，社区成员不限额；新用户通过你的邀请码注册并完成首次请求后，双方各增加 ¥5。费用由开发者承担，nanoMuse 是非营利社区项目，不收取费用。

  中继将对话、附图和屏幕操作请求转发到运营者在腾讯云部署的 `Qwen/Qwen3.6-27B-FP8`。项目托管服务不生成图片或视频，这些请求只发往你用自己 key 配置的服务商。

  中继保存的账号信息包括：手机号或邮箱的加盐哈希（用额外值参与计算，避免直接保存原地址的标识）；加密保存的原地址，供运营者识别账号，仅凭数据库文件无法读取；例如 `s***@example.com` 的打码提示；本设备所获 key 的哈希；各请求类型、模型及 token 数，token 是模型输入、输出的计量单位；邀请码及使用它的账号 id；智能体名字和形象，供各设备保持一致。形象信息包括使用哪张脸；若由形象工作室绘制，还包括对应的状态图片。1.0.7 起也保存某台设备已生成的形象短视频，使其他设备无需重复生成。

  中继 0.28 起，还记录每次对话请求的性能信息：等待模型可用名额的时间、首个 token 和完成时间、结束方式、消息数、图片数、App 提供的工具名、模型实际调用的工具名、是否属于屏幕操作，以及客户端平台。这些性能记录不含对话文字，保留 90 天，运营页面仅使用汇总结果。

  每次登录、请求、时间线事件和设备连接，还会记录来源网络地址及客户端软件信息，即 `User-Agent`，例如 Android App 及版本、Windows、macOS 或 Linux 运行时、浏览器。账号保留首次和最近一次地址，以及最近在线时间。运营者可按账号、按地址查看，以判断一个人使用两个账号、两个人共用一个地址等情况，并分析故障范围。

  中继 0.29 起保存完整的**请求记录**，即它回答过的每一轮聊天。内容包括实际发给模型的完整请求和模型原始回答：系统提示词及其中的记忆、SOUL、指令，你的消息、工具返回内容、截图和图片。这些是账号自己的数据，用于让各设备显示相同历史及截图，也让运营者能查看完整故障过程。图片以哈希为文件名去重保存，每张只存一份。1.0.7 起，App 提供设备和对话标识时，记录还会关联到对应设备和对话。

  你的设备可经中继读取记录，运营者也能读取，其他人无权读取。文件仅向所属轮次对应的账号开放。记录会保留到你在 设置 → 数据控制 删除，或删除账号为止。在数据控制页可一次删除全部请求记录及下文的训练轮次。自行部署的中继可用 `RECORD_KEEP_DAYS` 设置保留期限，或设 `RECORD_TURNS=0` 完全不保存请求记录。图片存储总量受 `MEDIA_MAX_GB` 限制，超出时先删除最久未使用的图片，文字继续保留。

  1.0.7 起，App 用自己的 key 完成的轮次也会上传到请求记录，使不同模型来源的历史保持完整。中继 0.31 起，App 会为每轮注明来源：用户、定时任务、动态例程、目标检查或其他设备；该轮在对话中的序号、本轮第几次模型调用，以及所属屏幕任务和步骤。中继还会用 `zh`、`latin`、`ja` 等代码标明用户文字所用的文字系统，此项不记录原文。

  App 也会以短代码和数字，报告该轮相关事件，不用文字描述：哨兵（Sentinel，执行前检查风险与授权的组件）如何判定工具调用及风险等级、审批（请你确认是否允许操作）的结果、你主动选择提供的停止回复原因、回答的赞踩，以及屏幕步骤结果。这些报告随轮次或账号一并删除。对话的其他用途由后文两个开关决定。

  App 从不向中继发送位置。运营页面显示的网络地址对应国家、省、市，来自中继磁盘上的离线 ip2region 公开数据库，在显示页面时查询，不请求第三方，也不保存查询出的地区。退出登录会吊销 key；删除账号会删除上述数据，包括网络地址。中继源码在 `cloud/`，部署说明见 [docs/cloud.md](cloud.md)。使用自己的 key 时，模型请求直接发送给服务商；如果同时未登录 nanoMuse Cloud，也不会向中继上传账号记录。使用自有 key 但仍保持登录时，前文的记录与数据控制规则仍然适用。
- **访问项目网站 nanomuse.cn 时**。 网站服务器保留七天访问日志，随后删除。脚本将日志汇总为每日页面访问量、访客数、各文件下载次数和来源网站。每日访客去重使用网络地址和浏览器信息的哈希，加入每天随机生成、两天后丢弃的盐值。原始日志保留的一周之外，不再保存地址；数据不共享，不使用 cookie 或第三方统计。中继运营页面的每日登录数、账号数也来自前文已有记录，不额外收集数据。
- **使用在线体验 demo.nanomuse.dev 时**。 页面不设置 cookie，网站服务器也不保留访问日志。启动 Muse 前，需通过体验网关登录 nanoMuse Cloud。网关把你的网络地址转交中继，中继按前文方式记录此次登录。

  网关数据库为每个账号保存账号 id、中继提供的打码提示、使用手机号还是邮箱、登录次数，以及首次和最近一次登录或体验时的网络地址和浏览器信息。每次体验还单独记录开始时间、来源地址、浏览器、是否使用自己的 key、结束方式，以及模型调用次数、token 数、图片和短视频数量。浏览器保存三十天有效的登录凭据，网关仅保存其哈希。

  你的消息经网关发送到运营者配置的模型，公共体验站使用阿里云百炼。网关只统计调用和 token，不保留消息内容。自己的 key 仅在此次体验期间保存在网关内存中，不写入磁盘。每次体验使用独立容器，三十分钟后或闲置十分钟后，容器及其中全部内容会删除。启动时会发送浏览器的时区名称，让 Muse 使用你的时间，该名称不保存。

  网关日志仅用 id 标识会话，用打码提示标识访客，不写入网络地址；Docker 最多保留 100 MB 日志。账号和体验记录没有自动删除期限，由运营者删除。中继运营者可在运营页面账号旁查看这些记录。源码位于 `demo/showcase/`，各限制详见该目录 README。
- **数据控制中的「帮助改进 nanoMuse 的 AI 模型」**。 各 App 的 设置 → 数据控制 都有此开关。开启时，你与 nanoMuse Cloud 模型的聊天文本可用于训练社区自己的开放模型，包括你的消息、模型回答、所选工具调用、模型信息、token 数，以及请求头中的 App 平台和语言。

  训练集不包含系统提示词，即你的记忆、SOUL、指令，也不包含工具结果、图片、音频和短视频，这些内容会替换成标记。训练轮次仅关联账号 id，训练导出不包含账号 id、网络地址或打码提示。中继 0.28 起，每条保留轮次还附带结构统计：消息数、字符数、工具调用数、图片数、提示是否过短，以及你输入内容的哈希，以便不读取文本就能统计重复。删除轮次时，结构统计也会删除。

  中继 0.31 起，开关开启时，用自己的 key 执行并上传请求记录的轮次，也按相同规则进入训练集。每条还注明来自用户还是例程、第几轮和第几步、使用中继模型还是自己的 key，以关联前文的赞踩和停止原因。

  训练导出以化名标识账号。化名是只有中继才能计算的带密钥哈希，没有密钥无法反推出原信息。你删除保留数据或账号时，中继会在删除台账中留下该化名和时间，不保留其他关于你的信息，供使用较早导出的训练集在下次构建时剔除你的轮次。此开关只决定哪些内容进入训练集，不决定前文完整请求记录是否保存。

  **在 `cloud.nanomuse.cn` 上，中继 0.9 起新注册账号默认开启此开关；更早账号沿用原来的选择**。 开关旁明确说明默认状态。自行部署的中继可用 `IMPROVE_DEFAULT` 设置。你随时可关闭，关闭后不再新增训练数据，也可在同一页一次删除此前保存的训练轮次和完整记录；删除账号也会清除。免费额度与此开关无关。1.0.7 之前的 App 仍使用旧说明，未提及完整请求记录，请以本页为准。
- **对话同步，中继 0.19 起登录后默认开启**。 对话文字保存在 nanoMuse Cloud，让同一账号的各设备显示相同聊天。此开关不上传文件或图片，每轮图片属于前文的完整请求记录。在 设置 → 数据控制 可关闭同步并删除已存内容；一台设备删除聊天后，其他设备也会删除。文字以原文保存，只有你的设备和中继运营者能读取，运营页面仅显示数量，不显示文本。

  具体保存：对话标题、发起设备，各消息的角色、文本、时间和设备，以及附件名称和大小。不保存文件、图片或工具结果。发给其他设备的聊天，以及本机替其他设备执行的聊天，不参与同步。每账号最多保留 20 000 条消息，单条超过 16 KB 会截断，详见 [docs/cloud.md](cloud.md#conversation-sync)。0.1.38 起默认只同步主要聊天。旁聊留在创建它的设备，其他设备的旁聊也不下载，除非在该设备开启「同时同步旁聊」。一台设备正在回答时，其他设备会收到如「kwai 正在处理…」的提示。这类提示仅通过中继内存转发，不写入存储，十分钟后清除。
- **设备互相调用，中继 0.9 起提供**。 开启「设备」后，已登录 App 会各自保持一条到中继的连接，让手机可以要求电脑执行任务，电脑也可调用手机。中继为每台设备保存一条记录：App 自选的设备 id、你设置的名字、手机或电脑类型、操作系统、App 版本、支持的动作、首次和最近在线时间、来源网络地址。其他设备在 设置 → 设备 看到同一列表，其中显示名字、类型、版本、在线状态和地址。

  1.0.7 起，设备记录还包括两个 id，说明该设备由哪个服务商和模型回答。账号模型记为 `cloud`，否则为你配置的服务商和模型，如 `openrouter`、`bailian`、模型 id，不含 key、Base URL 或其他设置。运营页面据此查看用户配置的服务商。

  设备之间发送的命令、文件、屏幕操作，以及手机经电脑转发的服务商请求，只在账号内部经过中继，不保存。中继日志仅记设备类型及设备、账号 id 的前几个字符，不记内容。「忘记」会删除离线设备的记录，退出登录会让设备离开 hub（设备互联）。
- **智能体访问网络时**。 网页搜索、网页抓取、App 内浏览器、MCP 服务器（通过通用协议向智能体提供工具或数据的服务）和命令行工具，会访问各自对应的网站或服务。发送内容取决于你交给智能体的任务。
- **检查更新时**。 手机、独立 harness 和旧桌面外壳先查询项目下载索引 `nanomuse.cn/dl/index.json`，无响应时再查询 GitHub API。自行运行的运行时，包括 `nanomuse serve`、Docker，每天检查一次，设置 `server.update_check = false` 可停止。Windows x64 桌面版在启动后及每六小时检查 Windows 更新元数据，先访问下载镜像，再访问 GitHub，设置中也可手动刷新。更新库会发送本机随机生成的分批发布标识，`User-Agent` 包含 App 名称和版本。自动下载默认开启，可在设置中关闭。Windows 网络计费状态仅在本机读取，计费网络或状态未知时等待手动下载，该分类不发送给更新来源。对话、账号凭据和设置均不发往更新来源。
- **远程备份时**。 选择 SMB、WebDAV、SFTP、S3、FTP 等远程目标后，备份会发送到该目标，并用你设置的密码加密。

## 权限 {#permissions}

App 只在功能需要时请求权限，并只用于相应功能：通知用于智能体状态和提醒；无障碍服务用于操作其他 App 屏幕，默认关闭，由你开启；存储权限限于你挂载的文件夹；麦克风用于语音输入；通讯录、日历、位置各自用于同名工具，必须授权后才能调用。App 不会在后台读取这些信息。

## 哪些操作需要先确认 {#what-the-agent-may-do-without-asking}

删除文件、向外发送消息或数据、付款等无法撤销的操作之前，智能体会暂停，并通过卡片请求确认。终端、浏览器和手机屏幕遵循相同规则。卡片可记住的授权分为三档，设置 → 权限 → 记住的授权 按同样分组列出，逐条可点按撤销：

- **执行后告知**：安装软件不先询问，智能体完成后说明。
- **先确认，可记住授权**：删除和发送可选「本次对话都允许」，或「对『X』总是允许」。X 限定为一个文件夹、收件人、网站或 App。
- **最高风险，在付款时逐次确认**：购买、下单、预订、交易、转账不提供「本次对话都允许」。可以选择「记住，下次在 X 里直接执行」，但只限一个 App 或网站，保存时须通过指纹、面容或 PIN 验证设备锁屏。此类授权排在权限页最前，每笔凭此执行的付款都会在聊天中明确告知。

智能体不会输入密码、验证码或卡号，遇到这些页面会交还给你。清空磁盘、强制推送覆盖历史、下载脚本后直接交给 shell 执行等危险命令，每次都须确认，不能记住授权。你明确要求的购物和交易可以执行；违法或有害的行为无论怎样表述，智能体都会拒绝并说明理由。

## 反馈 {#feedback}

设置 → 反馈 会向 GitHub Issues 提交问题，预填内容只有 App 版本和设备型号。不要在问题中粘贴 API key 或私人对话。

## 页面更新 {#changes}

App 的数据处理行为变化时，本页也会更新，修改历史可在仓库查看。[nanomuse.cn/privacy](https://nanomuse.cn/privacy/) 提供相同的中英文说明。
