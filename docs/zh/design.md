# 界面设计与设计理由 {#设计-nanomuse-长什么样-为什么这样}

本页记录 App 的外观规范和设计理由，供后续开发保持风格一致，也帮助贡献者区分既定设计与尚未实现的功能。小龙形象、布局和颜色变量均由项目自行设计。小熊猫相关内容仅用于保留早期设计记录。

本页的设计变量（design token）是可复用的颜色或样式名称；胶囊栏是底部圆角导航栏；「房间」指动态、点子、目标和资源库等功能页面。CSS 是控制网页外观和动画的样式语言，SVG 是可缩放的矢量图格式。

## 界面结构 {#the-shape-of-the-app}

| | nanoMuse 的做法 | 在哪里 |
|---|---|---|
| 背景与配色 | 浅色模式接近纯白，深色模式接近纯黑。不使用背景渐变，卡片基本不加阴影。用在小标签和标签栏上的 `surface-2` 灰色区分层次。颜色变量为 `bg`、`surface-2`、`fg` 和 `muted`，强调色为少量使用的饱和蓝 `#0064d4`。深色模式遵循 `prefers-color-scheme`，即系统的深浅色偏好。手机和网页版的浅色聊天背景均为纯白，手机的底栏、菜单和抽屉面板也为纯白；深色聊天在手机上为纯黑，在网页版上接近纯黑。蓝色仅用于链接和状态行 | `web/src/index.css`、`android/…/values/colors.xml`、`android/…/ui/theme/ChatColors.kt` |
| 字体 | 内置 [Figtree](https://github.com/erikdkennedy/figtree)，采用 OFL 开放字体许可证。全界面使用同一字体族，以三四档字号区分层级。文字尺寸偏大，标题字距较紧，消息气泡中的行距较宽 | `web/public/fonts/` |
| 聊天 | 手机和网页版都使用单色圆角气泡。深色主题下，用户消息为白底黑字；浅色主题下为黑底白字。智能体气泡与背景相差一级明暗。发送按钮和「回到最新」按钮使用相同的 `ink` 前景色。顶部通过渐隐遮罩与聊天内容衔接，消息可从其下方滚过。每次工具操作都有说明标签，例如「正在查价格」，展开后可查看调用详情。审批卡片显示哨兵（Sentinel，检查操作权限的组件）的摘要、完整动作和授权范围：一次、本次对话、总是；手机对应一次、本聊天、总是。生成的文件显示为带预览的方块 | `web/src/screens/ChatScreen.tsx`、`web/src/components/`、`android/…/ui/chat/ChatScreen.kt` |
| 形象 | 默认使用内置小龙。形象随空闲、工作、等待、完成、出错等状态切换，除出错外还配有循环短片。用户也可以使用形象工作室生成的形象，或带底色的 emoji。早期小熊猫的设计记录见下文 | `web/src/components/Avatar.tsx`、`web/public/avatars/` |
| 顶部与智能体面板 | 聊天顶部的圆形区域显示形象，下方依次是名称和状态行，例如「正在查价格」。点击形象打开面板，可查看大图、状态、当前任务的「停止」按钮、审批、活动、权限、日程，以及记忆、技能、连接和设置入口 | `web/src/components/MuseHeader.tsx`、`web/src/screens/MuseSheet.tsx` |
| 导航 | 底部为五个不带文字的图标，分别对应聊天、动态、点子、目标、资源库。导航栏位于底边上方 12 px，采用半透明毛玻璃效果和细边框。当前页使用实心图标，底色为 `ink`，图标色为 `ink-fg`；其他页用 `muted` 色描边。聊天是首页，记忆、连接和设置从形象面板进入。窗口较宽时改用侧栏 | `web/src/App.tsx` |
| 功能页面 | 动态提供为用户撰写的内容，用户可反馈希望多看什么；点子按领域排列建议，点击后作为任务发送；目标列表显示进度，打开后可查看步骤和下次跟进时间；资源库按最新优先显示智能体生成的内容及预览 | `web/src/screens/FeedScreen.tsx`、`IdeasScreen.tsx`、`GoalsScreen.tsx`、`LibraryScreen.tsx` |
| 动画 | 动画仅用于状态变化、标签出现和形象活动。小龙与工作室形象播放短片，emoji 使用呼吸、摇摆或跳跃动画。除状态旁的小型加载指示外，不放置其他转圈动画。启用 `prefers-reduced-motion`（系统的减少动态效果偏好）后，全部动画停止 | `web/src/index.css`、`web/src/components/Avatar.tsx` |

## 早期的小熊猫形象 {#the-red-panda}

> 从 0.1.11 起，手机、桌面和网页版的默认形象均为内置小龙。小熊猫曾继续作为可选形象，直到 0.1.23 与六只玩偶一起移除。以下内容记录项目最初如何用形象姿势表示智能体状态。

形象随状态变化，可以直接告诉用户智能体正在处理任务，无须只靠加载图标。项目最初使用 SVG 绘制小熊猫：圆头、带环纹的小耳朵、奶油色的双颊、深色鼻子、带高光的大眼睛和环纹尾巴。SVG 的各部分可以随 App 状态调整姿势，无须切换照片。

选择小熊猫，是因为它体型小、颜色温暖、形象好奇，更适合作为小助手；大熊猫则容易让人联想到常见吉祥物和国家符号。图形尽量简化：组成部分少、眼睛大，每种状态主要改变一处表情，使它缩到 16 px 时仍可辨认。

较大尺寸使用 2.5D 效果，即在平面图形上用光影表现体积。毛发、身体和脸颊使用径向渐变，头顶加高光，下巴和身体下方加阴影，形成毛绒玩偶的圆润感。它没有采用真实 3D 渲染，因为这种方式不便用 CSS 改变姿势，文件也难以保持在几 KB。图形本身没有描边，靠平面形状上的柔和光影表现层次。

组件通过 `detail` 选择三个细节层级。未指定时，`detailFor` 会根据 `size` 自动选择：`mark` 用于不超过 28 px 的图标、标签栏和列表，采用纯色并放大头部；`avatar` 用于不超过 160 px 的形象，增加渐变；更大的 `hero` 增加高光、细致尾纹和道具。早期 App、Android 启动器和 MobileGym 启动器的图标都由同一套 `mark` 几何数据生成。数据集中在 `web/src/components/redPandaShapes.ts`，组件和资源生成器读取同一个来源。

| 状态 | 触发条件 | 小熊猫的表现 |
|---|---|---|
| idle | 当前没有任务 | 呼吸、间隔眨眼、左右张望、耳朵轻动、尾巴摆动 |
| working | `status.state == "working"` | 在小笔记本电脑前打字，头部轻动，眼睛看着屏幕 |
| waiting | `status.state == "waiting"`，且有待处理的审批或问题 | 举起一只爪子，旁边显示「!」气泡，并轻轻跳动 |
| happy | 任务刚从 working 变为 idle，持续 3 秒；或用户点击形象 | 弹跳、微笑，并出现两颗闪光 |
| error | 工具调用失败或被拒绝，持续 4 秒 | 抖动、皱眉，并出现一滴汗 |
| sleepy | App 已加载，但无法连接服务器 | 闭眼、缓慢呼吸，并显示三个 z |

`web/src/mood.ts` 根据状态决定持续显示的姿势，并根据状态存储记录的 `finishedAt` 和 `mishapAt` 短暂显示完成或出错表情。动画由作用于 SVG 分组的 CSS 关键帧实现。每个部件使用明确坐标，`transform-box: view-box` 和指定的变换原点保证旋转、缩放的轴心正确。列表与选择器可用 `still` 显示静止形象；`prefers-reduced-motion` 则停止所有动画。

0.1.23 之前，小熊猫头部还用于 `web/public/icon.svg`、`mark.svg`、PWA 图标、README 封面、Android 自适应启动器图标和 MobileGym 图标。PWA 是可以安装到设备上的网页应用。Android 图标使用森林绿底色和无渐变的头部；主题图标与状态栏版本采用眼、鼻、嘴镂空的单色剪影，以适应系统裁切和着色。

当时，`web/` 中的 `npm run mascot:assets` 从 `redPandaShapes.ts` 生成矢量图，`npm run site:mascot` 为网站生成六种状态，`python scripts/mascot_png.py` 将 PWA 图标和封面转为位图。所有版本使用同一份图形数据，避免分别绘制造成差异。`RedPanda.test.tsx` 保存平涂头部、剪影和 idle 状态大图的快照测试。现在 `web/public/icon.svg` 使用蓝色 N，绘制的默认形象为小龙；小熊猫文件已随玩偶资源一起移除。

## 配色与字体参数 {#colour-and-type-in-numbers}

网页版的颜色变量定义在 `web/src/index.css`：

| 变量 | 浅色 | 深色 |
|---|---|---|
| `bg` | `#ffffff` | `#181819` |
| `surface` | `#ffffff` | `#202022` |
| `surface-2` | `#f2f2f4` | `#2a2a2d` |
| `border` | `#e7e7ea` | `#333337` |
| `fg` | `#111112` | `#ffffff` |
| `muted` | `#6b6b71` | `#9d9da4` |
| `accent` | `#0064d4` | `#1793ff` |
| `ink`（发送和「最新」按钮底色，图标使用 `ink-fg`） | `#000000`，图标 `#ffffff` | `#ffffff`，图标 `#000000` |
| `bubble-user` 和文字色 `bubble-user-fg` | `#000000`，文字 `#ffffff` | `#ffffff`，文字 `#000000` |
| `bubble-agent` | `#f2f2f7` | `#2a2a2d` |

聊天顶部使用渐隐遮罩（scrim），让滚动内容逐渐融入背景。遮罩上边缘的 `bg` 不透明度为 80%，中部以下为 35%，底边完全透明。翻阅旧消息时，顶部 80 px 会完全过渡为 `bg`。

底部采用相同方式。消息可以从输入区和底部胶囊栏下方滚过，胶囊栏会模糊其背后的内容。阅读旧消息时，输入区上方有一段高度为 90 的 `bg` 渐隐区域，让文字逐渐消失，避免与输入框重叠。停在最新消息时，输入区背后仅有列表本身的留白。Android 由 `ChatScreen.kt` 的 `NmChatBottomLayout` 和 `nmBottomFade` 实现；iOS 从 1.0.4 起由 `NanoMuseComposerHost` 实现。1.0.3 及之前，iOS 列表在输入区上方结束，胶囊栏背后没有滚动内容，因此看起来像白色底块。

用户气泡中的链接沿用气泡文字颜色，并加下划线。深色网页版的智能体气泡与 `#181819` 背景的亮度差，与手机上 `#1c1c1e` 气泡相对纯黑背景的差异保持相近。

宽屏对话采用居中的 760 宽度列，即网页版切换侧栏前的聊天宽度 `max-w-[760px]`。消息、输入框和胶囊栏位于同一列。输入框与胶囊栏等宽，为列宽减去左右各 16 的边距。智能体回复气泡的最大宽度从 340 增至 600，对应 `wide:max-w-[600px]`。

iPad 在 regular width size class（系统判断为较宽的布局尺寸类别）下使用这一布局，由 `NanoMuseShell.swift` 中的 `NanoMuseColumn` 实现。手机或窄窗口继续按窗口宽度布局，胶囊栏最大宽度为 420，通常不会触及该上限。

Android 的聊天颜色定义在 `ChatColors.kt`，由 `scripts/rebrand.py` 生成：

| 变量 | 浅色 | 深色 |
|---|---|---|
| 背景（`background`） | `#FFFFFF` | `#000000` |
| 用户气泡（`userBubble`）及文字 | `#000000`，文字 `#FFFFFF` | `#FFFFFF`，文字 `#000000` |
| 智能体气泡（`assistantBubble`） | `#F2F2F7` | `#1C1C1E` |
| 发送与停止按钮（`sendButton`），图标使用背景色 | `#000000` | `#FFFFFF` |
| 链接与状态行（`link`、`thinking`） | `#015CFB` | `#58A6FF` |

iOS 使用相同配色。`NanoMuseFaces.swift` 中的 `NanoMuseTones.ink` 和 `onInk` 分别控制用户气泡、发送按钮及「回到最新」按钮的底色与内容色，智能体气泡使用 `agentPill`。背景沿用系统的白色或黑色。胶囊栏当前页的圆形指示器也使用相同的 `ink` 和 `onInk`，对应 `tabIndicator` 与 `tabIndicatorGlyph`，详见 [ios.md](ios.md)。

早期小熊猫的毛色为 `#d8632e`，亮部 `#ee8a4c`，暗部 `#9e3f18`；耳朵、尾纹和爪子的深色毛发为 `#bf4f23`。奶油色为 `#fff4e6`，从 `#fffaf2` 渐变至脸颊的 `#f3dfc6`；纹路为 `#2a1a14`，眼睛高光为 `#4a302a`，腮红为 `#f4a0a0`。App 内形象底色为 `#dcebdc`，旧标志底色为 `#2f7a5a`。`mark` 层级仅使用基础色。

字体统一为 Figtree，按 Tailwind 的字号体系设置：消息气泡为 15 px，状态行与说明为 12–13 px，标题为 17–20 px 半粗体。

## 名称与个性设置 {#identity-the-name-comes-first}

nanoMuse 初次打开时会询问自己的名字。设置后，顶部、通知和自我介绍都会使用该名称。

- 首次运行使用任务清单。先用三句话说明它能执行任务、关闭 App 后继续工作，以及重要操作前先询问，再列出「认识你的 nanoMuse」「添加模型」「连接邮箱、日历、通讯录」三项，其中连接服务可选。完成项会打勾，只有模型成功回应后才能点击「开始」。进度从保存的数据恢复，中途刷新不会丢失。
- 起名页允许输入 1–20 个字符，留空时使用 `nanoMuse`。页面提供三个中文和三个英文建议名及「换一批」，显示形象，并支持不超过 60 字符的介绍。还可以设置语气（正式、随和、活泼、简洁）、回复形式（简短、详细、要点列表）、其他自由填写的要求，以及智能体对你的称呼。这些设置分别写入系统提示词，即每轮发给模型的固定指示，对应 `nanomuse/server/service.py` 的 `Profile`，因此修改语气不必改动其他要求。
- 名称贯穿顶部、问候、审批和权限文案，例如「{name} 想要执行的操作……」，也用于命令行横幅 `nanoMuse v0.1.0 · Momo`、MobileGym 桥接标题和「你和 Momo」设置页。指代产品本身时仍使用 nanoMuse。
- 原始模型表单允许直接使用自己的 key（访问模型服务的密钥），无须注册项目账号。服务商按协议分组：兼容 OpenAI 的 Chat Completions、Responses API、本地或自定义端点。API 是程序调用服务的接口，端点是接收这些调用的服务地址。表单显示厂商说明、可切换显隐的密钥、申请密钥链接；Base URL 未含路径时补上 `/v1`。Ollama 或勾选「无需密钥」的自定义端点可以不填 key。模型列表优先从服务自身的 `/models` 获取，失败时使用内置目录，手动填写的模型不会被替换。0.1.18 之前的设计不提供 OAuth 订阅登录，也未计划在 1.0 中加入，目的是避免项目代持用户与服务商之间的账号。OAuth 是让应用获得服务访问授权的登录机制。后续设计已经变化：nanoMuse Cloud 提供起步免费额度，0.1.39 起也支持 ChatGPT 套餐登录；两种方式仍将密钥或令牌保存在设备上，由用户掌握服务商关系。当前行为见 [cloud.md](cloud.md) 和 [own-key.md](own-key.md)。

## 主要设计原则 {#choices-made-on-purpose}

- 手机操作过程可见。每一步以 `phone_act: tap "发送" …` 等形式显示在聊天中，手机上同时显示触点提示，让用户知道智能体正在操作哪里。
- 用户能随时停止。整个手机操作期间，屏幕上方持续显示胶囊浮层，包含形象、当前步骤和红色「停止」按钮。点击后会终止当前步骤、阻止后续动作，并让智能体转向询问用户。屏幕操作放在最后使用，优先尝试技能、网页抓取和浏览器；活动页会显示屏幕操作的使用情况。
- 审批明确授权范围。卡片提供「允许一次」「本次对话都允许」「总是允许」，三个客户端的中间范围含义一致。已保存的授权列在「权限」中，均可撤销。
- 功能也提供文本和接口。终端命令 `nanomuse chat` 使用同一个智能体和审批规则。各页面背后都有文档说明的 REST + WebSocket API：REST 用于请求和更新数据，WebSocket 用于保持连接并接收实时事件，其他前端也可以接入。
- 吉祥物使用绘图。早期绘图只有几 KB，能随状态改变姿势，也便于用于贴纸。
