# 屏幕操作回归测试 {#固定-gui-回归任务集}

GUI 是图形用户界面，即用户看到并点击的页面。回归测试是在修改程序后，重新检查既有功能是否仍按预期工作。这组测试使用模拟页面，不会操作你的真实 App。

任务集保存在 `tests/fixtures/gui_regression/cases.v1.json`，并带有版本号。其中的 20 个场景覆盖笔记输入与编辑、Unicode 输入（包括中文等字符）、搜索、设置、购物车、权限和更新弹窗、等待加载、返回、相似标签、无效点击后的恢复、同意和拒绝审批，以及让用户接管密码输入。

<div id="离线运行"></div>

## 离线运行 {#run-without-a-model}

在已安装开发依赖的仓库根目录执行：

```bash
python scripts/gui_regression.py
python scripts/gui_regression.py --case notifications-enable
python -m pytest -q tests/test_gui_regression.py
```

命令会在 `.gui-regression/` 下创建独立目录，保存 `report.json`、各场景的审计文件、截图和操作轨迹。只要有测试失败，程序就返回退出码 1。CI 通过 pytest 执行这些场景，并在 Ubuntu / Python 3.12 环境中生成参考报告。

参考模式使用 `MockLLM`（按预设脚本返回回答的模拟模型），不发送真实模型请求。它检查的是操作器、坐标转换、设备请求、重复操作检测、审批和结果校验器。操作器是反复读取屏幕并执行动作的组件。参考模式的分数不是真实 GUI 模型、Android 真机或桌面 App 的任务成功率。

模拟设备会保存当前状态，并根据操作按固定规则更新。它提供绘制的 PNG 截图和无障碍树（页面控件的文字、类型及位置列表），不会控制宿主机器上的真实应用。

<div id="使用配置的模型"></div>

## 使用配置的模型 {#run-a-configured-model}

```bash
python scripts/gui_regression.py --live --config config/config.toml
```

这条命令会调用 `[llm]` 中配置的真实模型，可能产生费用。测试仍使用相同的模拟场景和结果检查规则。模型必须能接收图片，并按操作器要求的 `mobile_use` 格式回答。每个场景最多执行 16 个操作步骤，超时和重试沿用模型客户端的设置。

运行器只使用模型客户端，不连接真实设备。测试界面按各场景预设的决定回应审批，不加载技能，也不执行任意 shell 命令（终端命令）。

<div id="判定方式"></div>

## 如何判断通过 {#what-passes}

每个场景都独立声明初始页面、可见控件、页面切换规则、预期最终页面、字段值、操作器的结束状态和最少审批次数。只有有效动作经过实际的哨兵（Sentinel，检查操作权限的组件）和 `PhoneAct` 后，模拟器才会更新状态。输入文字前必须先聚焦输入框，点击空白区域不会让任务自动进入下一步。

校验器会读取模拟器的实际状态，再与预期结果比较。如果模型没有执行操作就声称完成、保存了错误文本，或选错了控件，测试都会失败。拒绝审批的场景要求页面保持不变，操作器进入阻止状态；密码场景要求交给用户处理，且不能已输入密码。

报告分别标注 `reference`（参考回放）和 `live`（真实模型调用），记录模型名称、任务文件、通过率、按最近秩法计算的 P95 耗时、模型调用次数、服务商报告的输入和输出 token、模型响应耗时、审批次数、逐项检查结果及轨迹编号。P95 指按耗时排序后，95% 的样本不超过的那个值；token 是模型计算输入、输出用量的单位。

没有返回用量的调用单独计入 `calls_without_usage`，不会被当作零费用，也不会用估算的 token 数补齐。服务商客户端内部发生的重试不单独计入调用次数。比较不同代码版本时，应使用同一版本的任务集和相同模型设置。参考动作与预期状态分开保存，真实模型看不到参考动作。

评测器自行记录用量，不依赖任务预算或记忆检索功能的改动，可以独立安装、测试和回退。

<div id="添加任务"></div>

## 添加测试场景 {#add-a-case}

在 JSON 文件中添加唯一编号和状态图（页面及操作后如何切换的规则）。每个页面需要标题，最多包含六个可见控件。控件可以聚焦输入框或切换页面，页面也可以响应等待和返回操作。

为离线 CI 添加一组参考动作，再独立声明预期结果。同一场景内的控件编号必须唯一。pytest 会自动为每个场景创建测试。测试数据应全部为虚构内容，不包含个人信息。

这组场景为可重复的运行时回归测试提供了基础。后续可以增加真实设备轨迹和更复杂的模拟 App，以扩大覆盖范围。参考动作回放的结果不能作为模型智能水平的证据。
