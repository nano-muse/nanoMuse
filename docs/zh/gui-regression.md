# 固定 GUI 回归任务集

版本化任务集位于 `tests/fixtures/gui_regression/cases.v1.json`，包含 20 个场景：
笔记输入与编辑、中文输入、搜索、设置、购物车、权限与更新弹窗、等待加载、返回、
相似标签、无效点击后的恢复、审批同意与拒绝，以及密码接管。

## 离线运行

在安装过开发依赖的仓库根目录执行：

```bash
python scripts/gui_regression.py
python scripts/gui_regression.py --case notifications-enable
python -m pytest -q tests/test_gui_regression.py
```

命令在 `.gui-regression/` 下建立独立目录，保存 `report.json`、各场景审计记录、
截图和操作轨迹。失败时退出码为 1。CI 通过 pytest 执行场景，并在 Ubuntu /
Python 3.12 生成离线报告。

离线参考模式使用 `MockLLM`，不调用模型，验证操作循环、坐标转换、设备请求、
循环检测、审批和结果校验。分数不代表真实 GUI 模型、Android 真机或桌面应用的
成功率。设备是有状态的确定性模拟器，提供绘制的 PNG 屏幕和可访问性节点，
不会操作宿主机器上的真实应用。

## 使用配置的模型

```bash
python scripts/gui_regression.py --live --config config/config.toml
```

此命令会真实调用 `[llm]` 模型，可能产生费用，仍使用同一批模拟场景与结果断言。
模型需要支持图片及操作器的 `mobile_use` 响应格式。每个场景最多 16 个操作步骤，
并使用模型客户端配置的超时和重试设置。
运行器只使用模型客户端，不连接真实设备；审批由任务中声明的测试决策回答，
不加载技能，也不运行任意 shell 命令。

## 判定方式

每个场景分别声明起始页面、可见控件、状态转换、预期最终页面、字段值、操作器
结束状态和最少审批次数。只有经过真实 Sentinel 和 `PhoneAct` 的有效操作才会
改变模拟器状态。输入前必须聚焦字段，点击空白处不会推动场景前进。

校验器读取模拟器实际状态。只说完成而没有操作、保存错误文本、选择错误控件都
会失败。拒绝审批的正确结果是页面保持不变且操作器被阻止；密码场景的正确结果
是交给用户处理，且没有输入密码。

报告区分 `reference` 和 `live`，记录模型、任务文件、通过率、最近秩 P95 耗时、
模型调用次数、供应商报告的输入与输出 token、模型耗时、审批次数、逐项断言和轨迹编号。
缺失用量通过 `calls_without_usage` 单独计数，不当作零费用使用，也不以猜测的 token 数
填充。供应商客户端内部的重试不单独计入调用次数。
版本间比较应使用相同的任务集与模型设置。参考动作与预期状态分别保存，
真实模型不会看到参考动作。

评测器自行记录用量，不依赖任务预算或记忆检索的改动，可以独立安装、测试和回退。

## 添加任务

向 JSON 文件加入唯一编号和状态图。每个页面最多六个控件，控件可以聚焦字段或
切换页面，页面也可响应等待和返回。为离线 CI 添加参考动作，并独立声明预期结果。
同一任务内的控件编号必须唯一，pytest 会自动参数化全部场景。
测试素材应使用合成数据，不包含个人信息。

这批任务提供可重复的运行时回归起点。真实设备轨迹和更复杂的模拟应用仍需持续
补充，参考动作回放不能作为模型能力的证据。
