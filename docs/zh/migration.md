# 从其他助手迁移

你可以把选定的记忆和文本文档导入桌面版，再逐个配置常用服务。nanoMuse 目前不能把 Muse 导出的 ZIP 整包恢复为账号，也不能自动恢复其中的对话、连接器和标签。核对迁移结果之前，请保留原始导出文件。

## 哪些内容可以迁移 {#what-can-be-moved}

| 导出的内容 | nanoMuse 中的去向 | 能保留什么 |
| --- | --- | --- |
| 简短的事实与偏好 | **SOUL 与记忆 → 导入记忆** | 选定的文本，每行一条记忆 |
| 笔记和对话文字记录 | **资源库 → 导入 Markdown 文件…** | 文本文档，不是可继续的聊天会话 |
| 连接器定义与脚本 | 在**设置 → 连接器**中逐个配置 | 你实际配置的连接器或 MCP 服务提供的能力 |
| 标签或分类 | 导出中有这些信息时，保留在文档标题或正文中 | 仅保留文本，不导入为标签元数据 |
| 对话清单与资源文件 | 与原始归档一起保留 | 不自动重建轮次、附件或会话 ID |

迁移只能使用导出文件里已有的信息。如果标签或连接器文件没有导出，nanoMuse 无法从对话文字或清单中还原。请检查你拿到的文件，不同导出方式包含的内容可能不同。

## 导入选定的记忆 {#import-selected-memories}

1. 打开智能体资料页，选择 **SOUL 与记忆**，点击**导入记忆**。也可以从**设置 → 数据控制**进入。
2. 粘贴希望智能体记住的事实，每行一条。先检查内容，长笔记和完整对话放进资源库。
3. 先导入一小批，核对保存结果，再继续导入其余内容。

每批最多 **200 个非空行**，整理空白和行首列表标记后，每条最多 **400 个字符**。桌面记忆**总共最多 400 条**，包含已经保存的记忆。仅大小写或多余空白不同的行会视为重复，不会再次添加。比较时保留标点，因此负数和小数不会混为同一条。

当前实现会在任何一项超限时**拒绝整批导入**，保留原有记忆，不截短新内容，也不挤掉旧记忆。你可以拆分批次、自己精简较长的事实，或先检查哪些旧记忆不再需要，再重新导入。旧构建可能截短内容或移除旧记忆，请使用包含导入限额修复的构建，再迁移完整记忆。

如果导入的记忆无法写入磁盘，应用会显示错误，不会提示成功。新条目可能仍在内存中显示，请检查磁盘空间和写入权限，在关闭应用前重新导入相同内容。即使这些行已经被视为重复，重试也会再次保存。

桌面记忆只有文本和「导入的」等来源标记，没有 Python 运行时的 `category` 字段。运行时的 [`nanomuse memory add --category …`](cli.md#memory) 写入另一套记忆存储，不会给桌面记忆添加分类，也不能导入 Muse 标签。在桌面记忆里写 `[项目]` 这样的前缀只是普通文本，也计入长度限制。

## 把历史对话保存为参考文档 {#keep-conversations-as-reference-documents}

在**资源库**中打开**创建**旁边的菜单，选择**导入 Markdown 文件…**。支持 `.md`、`.markdown` 和 `.txt`，每个文件不超过 **2 MB**。较长的对话先拆成便于阅读的文件。导入时会把文件复制到资源库，重名文件会加上序号。

导入后，对话文字是一份文档，不会恢复聊天列表、角色、时间戳、工具调用、附件或可继续的会话。图片等资源仍与原始导出一起保存，转换文档后检查其中的资源引用。导入文本文件不会同时导入它引用的资源。

不要把其他产品的对话直接写入 harness 会话文件，也不要伪造中继同步记录。这些格式由 nanoMuse 的会话与同步流程维护，不是外部对话导入接口。

## 重新配置连接器 {#reconfigure-connectors}

先逐个列出需要的服务、操作、认证方式和依赖的本地文件，再到**设置 → 连接器**查找可用连接。自定义连接需要真正实现 MCP 的服务，并按该服务文档配置传输与认证。桌面版见[连接器设置](desktop-muse.md#settings)，Python 运行时见 [MCP 服务配置](configuration.md#mcp-servers)。

`connector.yaml`、`CONNECTOR.md` 等文件可以用来了解旧配置，但 nanoMuse 没有这种连接器格式的导入器。调用服务 API 的 Python 脚本不会自动变成 MCP 服务，需要先实现并审查 MCP 适配层，客户端才能发现和调用它的工具。仅复制脚本，或把普通客户端脚本填入服务启动命令，都不能补上这层适配。

通过连接器提供的配置入口填写凭据，运行时的密钥放进保险库。选择需要的工具与权限，先验证只读操作，再让连接器执行修改。把自己希望保留的偏好整理成事实，不要照搬其他产品的系统提示词，也不要把它的说明当成 nanoMuse 的工具与权限配置。

## 核对迁移结果 {#check-the-result}

对照预期新增且不重复的事实数量，核对导入的记忆条数。抽查文档正文和资源引用，确认每个重新配置的连接提供了预期的工具。在这些检查通过前保留原始归档；尚无导入路径的历史和元数据仍需要从原始归档查阅。
