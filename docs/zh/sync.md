# 手机数据保存在哪里，归哪个账号 {#手机上留着什么-又是谁的}

手机和平板可能由家人共用，也可能转交他人，测试时还会切换账号。本页逐项列出 nanoMuse 手机 App 保存的数据、保存位置和归属，并说明退出登录、切换账号、删除账号、重新安装时如何处理。数据可能属于账号、属于设备，或不属于任何账号。这套规则是 0.1.40 引入的约定 C12。0.1.39 的 C10 只规定了对话的归属，见 [every-device.md](every-device.md#whose-conversations-a-device-shows)。

## 规则 {#the-rule}

- **每个聊天都有归属账号**。 聊天首次出现在手机上时，归属于当时登录的账号；未登录时创建的聊天不属于任何账号。升级至 0.1.40 后首次运行 App 时，旧聊天也按这个规则分配。已同步的聊天沿用同步映射中记录的账号，其他聊天归当时登录的账号；当时未登录的则不归任何账号。
- **只显示当前账号的聊天**。 聊天抽屉、搜索、「聊天」标签页、「资源库」、「今天的聊天」、Siri 快捷指令，以及上传到中继的内容，都遵循这一规则。退出登录后，只显示未登录时创建的聊天，所有账号的聊天均会隐藏。中继是负责账号与设备间通信的服务器。
- **退出登录时询问是否保留本地数据**。 「把这个账号的聊天留在这台设备上」默认关闭。关闭时，手机会删除该账号的聊天、记忆、动态、目标、例程和形象。若已开启同步，中继仍保留聊天，下次登录可恢复。开启时，这些数据会单独存入该账号的文件夹，下次登录同一账号时原样恢复。切换账号和「使用其他服务器」也先经过这套退出流程。
- **删除账号时直接清除数据**。 中继上的账号和手机上属于它的数据都会删除，不再询问是否保留。之后用同一手机号或邮箱登录，会创建新账号，从空白数据开始。
- **登录凭据被拒绝时默认保留数据**。 例如，你在另一台设备上选择「在所有设备退出」，或者中继重置、发生错误，都可能让手机收到 `401`。手机无法让你补答退出时的保留问题，因此按保留处理：聊天继续保留，但根据归属记录隐藏；文件和偏好移入账号专属文件夹；中继 key（访问凭据）被删除。登录页会提示「这台手机上的登录已结束。重新登录即可继续；在那之前，你的聊天会留在这台设备上。」重新登录同一个账号 id 后，全部数据恢复；其他账号看不到这些数据。只有中继明确返回 `401 account_deleted`，表示账号已不存在，手机才会按删除账号的规则移除数据。
- **重新安装后从空白数据开始**。 Android App 不参与系统设备备份，配置为 `allowBackup="false"`，因此数据不会复制到 Google，全新安装没有聊天、记忆或 key。iPhone 判断为全新安装时，即 UserDefaults 中没有安装标记、没有服务商和聊天，会删除上次安装遗留的本机专用钥匙串条目，包括中继 key、OAuth 令牌（登录授权凭据）和环境变量。中继 key 仅保存在本机，不同步到 iCloud 钥匙串；0.1.39 保存的 key 会在首次启动时迁移到本机专用位置。如果从你自己的 iPhone 备份恢复，UserDefaults、文件和安装标记会一起恢复，程序会视为同一次安装。
- **数据归属使用 `account.id` 标识**。 这是中继分配的内部账号标识，与手机号、邮箱无关。磁盘上的账号文件夹使用它的哈希值（由原值计算出的固定标识）命名。数据分类在本机完成，不依赖中继配合，因此连接旧版中继时也遵循同样规则。

**iCloud**。 OpenMinis 上游提供的聊天、服务商 iCloud 同步，以及 iCloud 钥匙串，关联的是你的 Apple ID，与 nanoMuse 账号无关。设置 → iCloud 中的上游同步默认关闭。开启后，退出 nanoMuse 账号导致的聊天删除，也会像手动删除一样通过 iCloud 同步。单独保存的聊天可能同步到你的另一台 iPhone，但不附带归属记录；那台手机会把聊天归给当前登录的账号。归属记录文件、同步表和单独保存的文件夹，与 App 的其他数据一样，会进入 iPhone 设备备份。

代码位置：`NanoMuse/NanoMuseAccountData.swift` 负责归属、`leave`、`enter` 和钥匙串；还有 `NanoMuseSync.shows`、`dropTable` 和 `NanoMuseSignOutSheet.swift`。创建和启动时的接入点位于 `ChatStore.createSession` 与 `NanoMuseShell`。

## 中继 {#the-relay}


`POST /v1/auth/delete` 会删除账号关联的全部数据库记录，包括账号本身、key、设备、资料（名字、形象、连接器）、用量账本、事件、「数据控制」保存的对话和视频任务，以及同步的对话、消息和游标。游标是记录同步进度的标记。中继还会断开该账号的 hub（设备互联）连接。随 0.1.40 发布的中继也会清除该账号保存在内存中的实时「正在处理」提示。中继测试会先注册账号并填入所有相关表，再删除账号，检查各表中该账号的记录数均为零；随后用同一地址注册，确认获得新的账号 id 和空的同步存储。

删除后仍会暂时保留一类数据：该账号曾持有的 key 的 SHA-256 哈希，存在 `deleted_keys` 中，保留 90 天。这些记录不含账号 id、地址或设备，无法指向某个人。它们用于识别尚在使用已删除账号 key 的手机，并返回 `401 account_deleted`，而不是 `401 bad_key`。前者让手机删除账号数据，后者让手机先保留数据，等待重新登录。0.1.40 之前的中继对两种情况均返回 `bad_key`，所以手机会保留数据，不会丢失，只是账号文件夹继续等待恢复。

## 维护说明 {#for-the-maintainers}

0.1.39 中，删除账号后仍能看见的旧记录来自手机本地。没有同步映射的聊天，例如未开启旁聊同步时的旁聊、0.1.39 之前创建的聊天，当时没有归属记录，因此会在所有账号下显示，并上传到下一个登录的账号。中继端的数据实际已经删除。C12 为每个聊天补上归属，并规定退出时同时删除该账号的本地数据，除非用户明确选择保留。
