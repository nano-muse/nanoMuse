# nanoMuse 1.0.2 · Trim

🐉 **nanoMuse `1.0.2` “Trim”**: a pass over every part of the project after the first two days of 1.0, with the reports and pull requests that came in.

1.0.1 went out on 2026-10-10. Within a day two pull requests arrived: one found a gap in the Sentinel's policy, a tool on the always-ask list could be waved through in auto mode after a private read ([#291](https://github.com/nano-muse/nanoMuse/pull/291)); the other found that the desktop's permission card no longer came up when the runtime refused a step of the hands ([#292](https://github.com/nano-muse/nanoMuse/pull/292)). Reports came in beside them: the Android app died on start on a phone that also has OpenMinis ([#271](https://github.com/nano-muse/nanoMuse/issues/271), [#288](https://github.com/nano-muse/nanoMuse/issues/288)), the Linux desktop ended on the first picture it read ([#274](https://github.com/nano-muse/nanoMuse/issues/274)), Windows drew its caption buttons over the buttons of several pages ([#272](https://github.com/nano-muse/nanoMuse/issues/272)), and the memory tidy-up approved an invented fact in Russian ([#270](https://github.com/nano-muse/nanoMuse/issues/270)). This version fixes all of them.

Then we went through the whole project ourselves, the runtime, the relay, the web console, the desktop, both phone apps, the docs and the workflows, and fixed what we found: errors that showed a status code instead of a sentence, command options with no help, a misspelt config key dropped without a word, an MCP server's key in a log line, thirty-eight iPhone strings in two languages only, dashes where the docs promised none. Nothing moves for a person upgrading: the Android package installs over 1.0.1 and keeps everything, the desktop keeps its settings, and a 1.0.1 client works against the relay (0.24.1) unchanged.

## Highlights

- **The Sentinel's taint rule holds in auto mode.** Step 5 of the policy, which marks a tool's ask as one that auto mode may not skip once private data has been read in the conversation, ran only when the decision so far was *allow*; a tool in `always_ask_tools` such as `shell` or `send_email` had its ask marked as skippable, so an unattended pass could run a `curl` to a host nobody allowlisted, or mail the data it had just read, with no approval. The check now runs on every decision and can only escalate, so that ask stays an ask in every mode; `docs/sentinel.md` says so in both languages ([#291](https://github.com/nano-muse/nanoMuse/pull/291), by @hobostay).
- **The Android app starts beside OpenMinis.** Both apps bound the same Linux abstract socket, `native-offload`, for the sandbox's calls back into the app, and abstract sockets are one namespace for every app on the device, so whichever app started second died before its first screen. nanoMuse's socket is now `io.github.nanomuse.app.native-offload`; when even that is still held by a previous process of ours, the app binds a per-process name and tells proot that one instead of crashing. If even that fails, the crash names the socket that failed and says that another process may hold the namespace ([#271](https://github.com/nano-muse/nanoMuse/issues/271), [#288](https://github.com/nano-muse/nanoMuse/issues/288)).
- **The desktop's permission card is back for the hands' refusals.** The runtime has written its refusal of a step as `Not done: ` since 1.0 while the desktop looked for the em dash form only, so a step the runtime held back (Enter, a submit, a click on a word from the sensitive list) failed without the card and without the ticket. Both marks are recognised now, and the plugin's own decline of a step carries the colon too ([#292](https://github.com/nano-muse/nanoMuse/pull/292), by @hobostay).
- **On Linux a picture no longer kills the harness; on Windows the caption buttons cover nothing.** Electron's Linux binary leaks the system's GLib symbols into the process and sharp's native libvips carries its own; the clash printed `GLib-GObject-CRITICAL` on every picture and, on some systems, ended the harness with a SIGSEGV on the first picture it decoded. The Linux package now ships sharp's WebAssembly build; a picture takes about twice as long (some 50 ms for a 2560×1440 screenshot) and the clash is gone; macOS and Windows keep the native build ([#274](https://github.com/nano-muse/nanoMuse/issues/274)). On Windows the minimise, maximise and close buttons the system draws over the top right corner sat on top of the buttons at the right end of several pages' top bars (*Select*, *Sort* and *Create* in the Library, *More* and *Close* in the document editor, *Refresh* and *Add plugin* on Plugins, *New* on Schedules, and others); those bars now leave the caption buttons' width free, read from the window rather than a fixed number ([#273](https://github.com/nano-muse/nanoMuse/pull/273), by @jiangkaiqi2005).
- **The memory tidy-up judges every script, and refuses what it cannot judge.** Its tokenizer knew Latin letters and CJK only, so a Russian (or Greek, Arabic, Hebrew) merge had no words to compare and the guard against invented facts approved anything, while recall between two Russian lines scored zero. Words are now Unicode words in any alphabet, a word that only differs from a source's by its ending counts as the same, and when there is nothing to compare the merge is refused rather than waved through ([#270](https://github.com/nano-muse/nanoMuse/issues/270)).
- **The runtime says what is wrong, once.** A second `nanomuse serve` on a busy port names who holds it (another nanoMuse, with its version, or another program) and stops with exit code 98, before anything starts. `nanomuse doctor` says each thing once, ends on its summary instead of printing `error: Exit: 1` under it, and lists the config keys nothing reads: a misspelt key (`modle` under `[llm]`) or one from another version used to be accepted without a word, so the default applied and nothing said why; the loader now logs each such key with its path. Every option of every command has a help text, the help no longer breaks its lines mid-sentence, `nanomuse channels` and `nanomuse chatgpt` name each setting they cannot read like the other commands do, and when a hosted MCP server refuses its key the warning masks the query string (`?key=***`) instead of writing the full URL to the console and to `logs/`.
- **A refused request says a sentence in your language.** In the web console, a request the runtime refused without a sentence of its own used to show the HTTP status text or the raw JSON body; it now says *Your nanoMuse hit a problem; try again in a moment.* or *Your nanoMuse could not do that.*, in English and Chinese, and the runtime's own sentence still comes through when there is one. On the desktop the Media, Studio, Coding and Tasks pages, the own-key provider list and a document's editor printed the bare status number (`500`) and a sign-in no longer valid came through as the relay's English words; they now use the same wording as the rest of the app. The sign-in and profile forms' fields are labelled for screen readers, and the Chinese Settings section is titled *nanoMuse Cloud* like the English one.
- **One more provider in the own-key catalogue: OpenCode Zen.** A key from [opencode.ai/auth](https://opencode.ai/auth), pay per request from a balance, a few of its models free; chat only, on the OpenAI shape, since the GPT, Claude and Gemini ids on the same host speak other shapes and the one vision model OpenCode lists is an id DeepSeek has retired. A catalogue lookup now tries the whole address before the host, so two providers on one host no longer resolve to the first. OpenCode Go, the subscription on the same host, stays out for now: it asks a client to identify itself and send a session header on each request, which nanoMuse does not do yet (thanks @PovedaAqui). The relay (0.24.1) carries the same catalogue, so the apps' own-key card lists the entry on every client.
- **The phones' strings.** iPhone: thirty-eight of nanoMuse's own strings (the account page, the About credits, the feed and goal prompts, the chats drawer) had English and Chinese only and fell back to English elsewhere; they now carry all nine languages, and a test holds every string the app's own views use to that. Two Russian sentences lose the dash they used as a copula, and the Chinese lines that insert a device or agent name put a space around it. Android: the private-address hint writes `172.16-31.x` in all seventeen languages, and the Chinese Sentinel card and the *Connected on another device* lines space the names they insert.
- **The project around the code.** Every page under `docs/`, English and Chinese, reads without em dashes (about 1 900 lines across 68 pages); the configuration reference and `config/config.example.toml` name every key; the Chinese `hub.md` and `cloud.md` say what the English ones say and seven in-page links on the site land where they point. The showcase's lines to try are one set per language and each was run end to end before it stayed (张伟 now invites to a hike, so the two-app line has a reason to read tomorrow's weather; the demo Muse runs on the visitor's clock). The READMEs in ten languages carry a note on where nanoMuse is going, a *Maintainers* card, the *Community Contributors* avatars, a visitor counter that carried over the earlier count, and the Trendshift badge (number seven on GitHub Trending's Swift list on 2026-10-10). *iOS · build check* runs on every pull request that touches the iOS tree, and the lock-file check covers every npm lock file on every pull request.
- **TestFlight.** Build 16 (1.0.0) is what the public link installs today; build 18 (1.0.1) has been waiting for Apple's beta review since 2026-10-10; 1.0.2 goes up as build 19 and is submitted to the same review. The link installs a build once its review has passed, the internal testers before that.

## Upgrade Notes

- **Android installs over 1.0.1 and keeps your data.** `nanoMuse-1.0.2-arm64.apk` (Android 8.0+, arm64; versionCode 45) is signed with the same key as every version before it. Verify with `sha256sum -c nanoMuse-1.0.2-arm64.apk.sha256`. A phone that also has OpenMinis installed: nothing to do, both apps start now.
- **iPhone and iPad come through TestFlight.** The public link installs build 16 (1.0.0), which passed Apple's beta review; build 18 (1.0.1) is still in that review, and build 19 (1.0.2) is submitted when it is uploaded; a build reaches the link once its review has passed, the internal testers before that.
- **The desktop installers are built by CI from the tag `v1.0.2`.** The Mac packages are not notarized: the first time, open the app from *System Settings → Privacy & Security → Open Anyway* (or right-click → *Open*). The Windows package is not signed: click *More info* and *Run anyway* once. On Linux prefer the `.deb`; the AppImage needs FUSE (`--appimage-extract-and-run` without). They arrive a little after the APK, and `SHA256SUMS-desktop.txt` lists every checksum. The Linux package reads pictures with sharp's WebAssembly build: about twice as long per picture, no crash.
- **The runtime's commands changed what they say, not what they take.** `nanomuse doctor` now lists a config key nothing reads as a problem and exits 1 until the key is fixed or removed; a second `nanomuse serve` on a port a nanoMuse already holds exits 98 with the holder's name ([docs/troubleshooting.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/troubleshooting.md) has the entry). `config.toml` keeps every key it had.
- **The relay is 0.24.1; nothing changes on the wire.** A 1.0.1 client works against it unchanged. The one difference an operator sees is the own-key guidance, which now lists OpenCode Zen; [docs/self-hosting.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/self-hosting.md) says how to update a relay of your own.

## Community

nanoMuse is open source, free and non-profit. Sign in with a phone number or an e-mail and you get a starting allowance; the developer pays for it. The account page shows what is left and how to add more. When it is gone, use your own key or a plan you already pay for ([how](https://github.com/nano-muse/nanoMuse/blob/main/docs/own-key.md)); the key you add can take over any of the four jobs, and the account can be switched off as a model source while you keep it for sync and your devices. With an account, the text of your main conversation is kept on nanoMuse Cloud so that your devices show the same chat, side chats only if you say so, and one switch in Data controls turns it off and deletes it; nothing is sold ([privacy policy](https://nanomuse.cn/privacy/)); delete the account whenever you want. The same relay runs on a server of yours: [docs/self-hosting.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/self-hosting.md).

A stable version is not the last word. We use it every day and still know where it is rough; tell us where it broke for you and what you want it to do. The [roadmap](https://github.com/nano-muse/nanoMuse/blob/main/docs/roadmap.md) says where help is wanted, and [docs/parity.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/parity.md) says what each client has. 🐉 **nanoMuse `1.0.2`「Trim」**：1.0 发出两天之后，把项目的每一部分过了一遍，连同这两天收到的反馈和 PR。

1.0.1 在 2026-10-10 发出。一天之内来了两个 PR：一个发现 Sentinel 策略里的一个缺口，自动模式下读过私密数据之后，一个本该每次都问的工具可能被直接放行（[#291](https://github.com/nano-muse/nanoMuse/pull/291)）；另一个发现运行时拒绝「手」的某一步时，桌面端的权限卡不再弹出（[#292](https://github.com/nano-muse/nanoMuse/pull/292)）。反馈也来了：装了 OpenMinis 的手机上 Android App 一启动就死（[#271](https://github.com/nano-muse/nanoMuse/issues/271)、[#288](https://github.com/nano-muse/nanoMuse/issues/288)），Linux 桌面端读到第一张图就退出（[#274](https://github.com/nano-muse/nanoMuse/issues/274)），Windows 把窗口按钮画在了好几个页面的按钮上面（[#272](https://github.com/nano-muse/nanoMuse/issues/272)），记忆整理放过了一条俄语的编造事实（[#270](https://github.com/nano-muse/nanoMuse/issues/270)）。这个版本把它们都修了。

然后我们自己把整个项目过了一遍：运行时、中继、网页控制台、桌面端、两个手机 App、文档和工作流，发现什么修什么：只显示状态码不说人话的报错、没有说明的命令选项、拼错了就被悄悄丢掉的配置键、日志里的一行 MCP 服务器 key、只有两种语言的三十八条 iPhone 文案、文档里说好不用却还在的破折号。升级的人什么都不用挪：Android 安装包覆盖安装 1.0.1、数据全部保留，桌面端保留设置，1.0.1 的客户端对着新中继（0.24.1）照常工作。

### 亮点

- **Sentinel 的污点规则在自动模式下也成立。** 策略的第五步负责在对话里读过私密数据之后，把工具的询问标成自动模式不能跳过的那种；它以前只在此前的判定是「允许」时才跑，所以 `always_ask_tools` 里的 `shell`、`send_email` 这类工具的询问被标成了可跳过，一次无人值守的运行可以向没人放行过的主机发一条 `curl`，或者把刚读到的数据发邮件出去，没有任何审批。现在这一步对每个判定都跑，而且只能升级不能降级，所以这种询问在每种模式下都还是询问；`docs/sentinel.md` 中英文都写明了（[#291](https://github.com/nano-muse/nanoMuse/pull/291)，@hobostay）。
- **Android App 能和 OpenMinis 装在一起启动。** 两个 App 为沙箱回调 App 绑定的是同一个 Linux 抽象 socket `native-offload`，而抽象 socket 在整台设备上是同一个命名空间，所以后启动的那个绑定失败，还没到第一屏就死了。nanoMuse 的 socket 现在叫 `io.github.nanomuse.app.native-offload`；连它也还被我们自己上一个进程占着时，App 会绑一个按进程区分的名字并告诉 proot，而不是崩溃。连这都失败的话，崩溃信息会点名最后失败的那个 socket，并说明可能有别的进程占着命名空间（[#271](https://github.com/nano-muse/nanoMuse/issues/271)、[#288](https://github.com/nano-muse/nanoMuse/issues/288)）。
- **运行时拒绝「手」的某一步时，桌面端的权限卡回来了。** 运行时从 1.0 起把拒绝写成 `Not done: `，桌面端却只认破折号的那种写法，所以被运行时拦下的一步（回车、提交、点到敏感词表里的一个词）既没有卡片也没有工单就失败了。现在两种写法都认，插件自己拒绝某一步时也用冒号（[#292](https://github.com/nano-muse/nanoMuse/pull/292)，@hobostay）。
- **Linux 上读图不再弄死 harness；Windows 的窗口按钮不再盖住任何东西。** Electron 的 Linux 二进制把系统 GLib 的符号泄漏进进程，sharp 的原生 libvips 又自带一份，两者相撞在每张图上打印 `GLib-GObject-CRITICAL`，在一些系统上读到第一张图就以 SIGSEGV 结束 harness。Linux 包现在带的是 sharp 的 WebAssembly 构建；一张图的耗时大约翻倍（2560×1440 的截图约 50 毫秒），冲突没有了；macOS 和 Windows 保留原生构建（[#274](https://github.com/nano-muse/nanoMuse/issues/274)）。Windows 上系统画在右上角的最小化、最大化和关闭按钮压在好几个页面顶栏右端的按钮上（资源库的「选择」「排序」「创建」、文档编辑器的「更多」「关闭」、插件页和定时页右端的按钮等等）；这些顶栏现在在右侧留出窗口按钮的宽度，宽度从窗口读取，不是写死的数字（[#273](https://github.com/nano-muse/nanoMuse/pull/273)，@jiangkaiqi2005）。
- **记忆整理会判断每一种文字，判断不了的就拒绝。** 它的分词器以前只认拉丁字母和中日韩文字，所以一次俄语（或希腊语、阿拉伯语、希伯来语）的合并没有词可比，防编造的守卫什么都放过，而两条俄语之间的回忆得分是零。现在词是任何字母表里的 Unicode 词，只有词尾和来源不同的词算同一个，没有东西可比的时候合并被拒绝，而不是放行（[#270](https://github.com/nano-muse/nanoMuse/issues/270)）。
- **运行时把问题说清楚，只说一遍。** 端口被占时第二个 `nanomuse serve` 会说出是谁占着（另一个 nanoMuse 连版本号一起，或者别的程序），在启动任何东西之前以退出码 98 停下。`nanomuse doctor` 每件事只说一次，以摘要结束而不是在下面再印一行 `error: Exit: 1`，并且会列出没人读的配置键：拼错的键（`[llm]` 下的 `modle`）或别的版本的键以前被一声不响地接受，于是默认值生效、没人说为什么；现在加载器会把每个这样的键连路径一起记下来。每个命令的每个选项都有说明，帮助文字不再在句子中间断行，`nanomuse channels` 和 `nanomuse chatgpt` 像其他命令一样逐条列出读不了的设置，托管的 MCP 服务器拒绝 key 时，告警会把查询串打码（`?key=***`），而不是把完整 URL 写进控制台和 `logs/`。
- **被拒绝的请求用你的语言说一句话。** 网页控制台里，运行时拒绝请求又没给出自己的句子时，以前显示的是 HTTP 状态文字或原始 JSON；现在说「你的 nanoMuse 出了点问题，稍后再试。」或「你的 nanoMuse 没能完成这个操作。」，中英文都有，运行时自己的句子有的话照样显示。桌面端的「图像与视频」、形象工作室、「编程助手」和任务页、自有 key 的服务商列表和文档编辑器以前只印一个状态数字（`500`），失效的登录以中继的英文原话出现；现在和 App 其他地方用同样的措辞。登录表单和资料表单的输入框给读屏软件加了标签，中文设置里的那一节和英文一样叫 *nanoMuse Cloud*。
- **自有 key 目录多了一家：OpenCode Zen。** key 在 [opencode.ai/auth](https://opencode.ai/auth) 申请，按请求从余额扣费，有几个免费模型；只做对话，走 OpenAI 格式，因为同一域名上的 GPT、Claude、Gemini 走别的格式，它列的唯一一个视觉模型是 DeepSeek 已经退役的 id。目录查找现在先试完整地址再试域名，同一域名上的两家服务商不再都解析到第一家。同一域名上的订阅 OpenCode Go 暂时不收：它要求客户端表明身份并在每个请求上带会话头，nanoMuse 还没做（谢谢 @PovedaAqui）。中继（0.24.1）带着同一份目录，所以每个客户端的自有 key 卡片都会列出这一条。
- **手机上的文案。** iPhone：nanoMuse 自己的三十八条文案（账号页、关于页的致谢、动态和目标的提示、聊天抽屉）以前只有英文和中文，其他语言回落到英文；现在九种语言都有，一条测试把 App 自己的视图用到的每条文案都管住。两句俄语去掉了当系动词用的破折号，插入设备名或智能体名的中文在名字两边加了空格。Android：私有地址的提示在十七种语言里都写成 `172.16-31.x`，中文的 Sentinel 卡片和「已在另一台设备上连接」两行在插入的名字两边加了空格。
- **代码之外的部分。** `docs/` 下的每一页，中英文，都不再有破折号（68 页约 1 900 行）；配置参考和 `config/config.example.toml` 列出了每个键；中文的 `hub.md` 和 `cloud.md` 和英文说的一样，站点上七个页内链接指到了它们该指的位置。体验页的示例每种语言一组，每一条都跑通了才留下（张伟现在约的是徒步，这样两个 App 那条有理由先看明天的天气；演示的 Muse 按访客的时钟走）。十种语言的 README 多了一段说 nanoMuse 往哪去的话、一张「维护者」卡片、「社区贡献者」头像、一个接续了之前计数的访客计数器，还有 Trendshift 徽章（2026-10-10 在 GitHub Trending 的 Swift 榜上排第七）。*iOS · build check* 在每个改到 iOS 目录的 PR 上运行，lock 文件检查在每个 PR 上覆盖每一份 npm lock 文件。
- **TestFlight。** 公开链接今天装到的是第 16 个构建（1.0.0）；第 18 个构建（1.0.1）从 2026-10-10 起一直在等 Apple 的测试版审核；1.0.2 以第 19 个构建上传并提交同一审核。审核通过的构建就会给到链接，内部测试员在那之前就能用。

### 升级说明

- **Android 覆盖安装 1.0.1，数据保留。** `nanoMuse-1.0.2-arm64.apk`（Android 8.0+，arm64；versionCode 45）和之前每个版本用同一把签名。校验：`sha256sum -c nanoMuse-1.0.2-arm64.apk.sha256`。同时装了 OpenMinis 的手机：什么都不用做，两个 App 现在都能启动。
- **iPhone 和 iPad 通过 TestFlight。** 公开链接装到的是通过了 Apple 测试版审核的第 16 个构建（1.0.0）；第 18 个构建（1.0.1）还在审核中，第 19 个构建（1.0.2）上传后送审；哪个构建审核通过，链接就给到哪个，内部测试员在那之前就能用。
- **桌面安装包由 CI 从 tag `v1.0.2` 构建。** Mac 的包没有经过公证：第一次在「系统设置 → 隐私与安全性」里点「仍要打开」（或右键 → 「打开」）。Windows 的包没有签名：点一次「更多信息」和「仍要运行」。Linux 上优先用 `.deb`；AppImage 需要 FUSE（没有就加 `--appimage-extract-and-run`）。它们比 APK 晚一点到，`SHA256SUMS-desktop.txt` 列出了所有校验值。Linux 包用 sharp 的 WebAssembly 构建读图：每张图耗时大约翻倍，不再崩溃。
- **运行时的命令改的是说法，不是用法。** `nanomuse doctor` 现在把没人读的配置键列为问题，在修好或删掉之前以退出码 1 结束；端口已被一个 nanoMuse 占着时，第二个 `nanomuse serve` 以退出码 98 结束并说出占用者（[docs/troubleshooting.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/zh/troubleshooting.md) 有这一条）。`config.toml` 里的每个键都保持原样。
- **中继是 0.24.1，线上什么都没变。** 1.0.1 的客户端对着它照常工作。运维者能看到的唯一区别是自有 key 的指引里多了 OpenCode Zen；自己部署的中继怎么更新，见 [docs/self-hosting.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/zh/self-hosting.md)。

### 社区

nanoMuse 开源、免费、非营利。手机号或邮箱登录后有一份起始额度，钱是开发者出的；剩多少、怎么加，账号页里有数。用完可以换成自己的 key，或者用你已经在付费的套餐登录（[教程](https://github.com/nano-muse/nanoMuse/blob/main/docs/zh/own-key.md)）；你加的 key 可以接手四件事里的任何一件，账号也可以作为模型来源关掉，只留着做同步和管设备。登录后，主聊天的文字会保存在 nanoMuse Cloud，让你的几台设备看到同样的对话，旁聊只在你说要的时候才上去；「数据控制」里一个开关就能关掉并删除；数据不卖（[隐私政策](https://nanomuse.cn/privacy/)）；账号想删就删。同一个中继也能跑在你自己的服务器上：[docs/self-hosting.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/zh/self-hosting.md)。
