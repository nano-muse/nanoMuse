# nanoMuse 1.0.0 · Keel

🐉 **nanoMuse `1.0.0` “Keel”**: the first stable version, one personal agent for every device you own, and nothing in it that we would not run ourselves.

Since 2026-09-25 every version has been a preview. Forty of them later the set is complete: a phone app for Android and for the iPhone, a desktop app for the Mac, Windows and Linux, the web console, and the open-source relay, nanoMuse Cloud, that signs people in and lets their devices talk. One account across all of them, so the phone, the desktop and the browser show the same conversation. Hands on the phone and on the computer, which look at the screen and act for you, with an approval between the agent and anything you could not undo. A key of your own for any of eighteen providers, or the free allowance that comes with the account. Everything in one repository, GPL-3.0-or-later, non-profit.

1.0 means this: what is here works the way the docs say, an update installs over the last one and keeps your data, the three wire protocols (the hub frames, the conversation sync, the operator) are documented and a client one version behind keeps working, and we tell you in plain words when something is rough. It does not mean finished; the [roadmap](https://github.com/nano-muse/nanoMuse/blob/main/docs/roadmap.md) is as long as it was. Since 0.1.41 the changes are mostly about choice and about trust: nanoMuse Cloud can be switched off as a model source without signing out, the main chat follows the model you pick, the model pickers fold and can be searched, the Sentinel asks in `auto` mode where it used to allow, and the hub and the relay were hardened on both ends.

## Highlights

- **nanoMuse Cloud is a switch, not a wall.** *Settings › Models* on Android, the iPhone and the desktop starts with *Use nanoMuse Cloud models*, and the web console's nanoMuse Cloud card has the same switch; the runtime reads it as `[cloud] models = false` and `POST /api/cloud/models`. Off, the account's models leave every picker and the automatic order of the hands, pictures and clips, no side call (a chat's title, a compaction) runs on the relay, and the only thing that spends the allowance is the explicit *Use nanoMuse Cloud this time*; the sign-in, the conversation sync and your devices stay. Switching off is refused with one sentence while the chat model is still the account's, since nothing else could answer. A phone or a console with a key of its own now works signed out: the sign-in screen stands only when there is neither an account nor a provider with a key, and offers *Use your own API key instead*. On Android and the iPhone the nanoMuse Cloud provider row can no longer be deleted (that was the sign-out); its page says why and points to the switch.
- **The main chat follows the chat model you pick.** On 0.1.41 a chat pick on *Settings › Models* set the default for new chats only, and the main chat is never new, so a person who added a key saw their side chats answer through it while the main chat kept nanoMuse Cloud under the face. On Android, the iPhone and the desktop the main chat's binding now moves with the pick; a side chat keeps its model; the line under the picker says so; Android takes the group's thinking level along. A main chat on *Use nanoMuse Cloud this time* finishes that turn on the account and comes back to the pick.
- **The model pickers fold long lists and can be searched**, on every client. Each provider group shows eight models (the catalogue's default for the row first, then the one in use, then the rest as the provider lists them) and ends in *Show N more*; once the groups hold more than eight models in all, a *Search models* field filters every group by model id or display name as you type, and *No model matches* says when nothing does. OpenRouter or SiliconFlow no longer turns the picker into an endless list. On Android the search text and the opened groups survive a rotation, and *Automatic* and every row tell TalkBack and VoiceOver whether they are the chosen one.
- **A thinking level for a key of your own (desktop).** The composer offered a level only for the Cloud's known models. The provider catalogue (`providers.json`, the file every client carries) now records, per vendor and model pattern, how the vendor's own documentation controls the level, with the page it was read from, and the desktop declares those levels to the harness in the vendor's shape: `reasoning_effort` for OpenAI, Kimi, MiniMax, SiliconFlow, Volcengine, xAI, Gemini's OpenAI layer, Groq, Mistral and gpt-oss on Ollama or vLLM; `thinking` plus `reasoning_effort` for DeepSeek and Zhipu; OpenRouter's `reasoning.effort` with the levels its model list gives; Anthropic's adaptive thinking with `output_config.effort`. *Provider default* sends nothing. A key saved by an earlier build gets the levels at the next start; the phones read the same catalogue and ignore the field for now.
- **The star card has *I already starred*.** Next to *Star on GitHub* and *Not now*, on every card and every star row of every client, the new button says the star is done; it and *Star on GitHub* stop the asks on this device for good, whatever the cooldown and the asks left. A person who had starred from GitHub itself kept being asked; not any more.
- **The desktop waits for a slow start, knows its version, and offers the right package.** On a fresh Windows install the real-time scanner reads each of the app's 20 000 files on first open and the host came up seconds after the shell had given up with *the host did not announce its address within 120 s*. The shell now waits as long as the host process runs: *Still starting* with the host's last lines after two minutes, a dialog with *Keep waiting*, *Copy details* or *Quit* after ten. The installed app ran as `0.0.0` (the version came from an environment variable nothing set), so the daily update check saw every release as newer and the hub was told `dsh-nanomuse 0.0.0`; the version is baked in at build time now and the check compares bare numbers. About offers the `.deb` on Linux and the AppImage only when the running app is one. A Cursor or Claude Code workspace on Windows reads back as `C:\Users\me\app`, which is also what broke the 0.1.41 desktop build. Settings keeps *Back to {page}* when one page opens another; a failed call to the relay is one plain sentence in English and Chinese instead of the wire's text; Enter while an input method is composing no longer sends.
- **The reply follows the language of the app.** The system prompt named only the script of the latest message, so an English console with a short or mixed message got a Chinese answer about half the time. A client may now send the language of its screens with each message (`language`, a BCP-47 tag, on `POST /api/threads/{id}/send`, the socket's `send` frame and the hub's `task` call); the prompt names that language first and the message's script second. The web console sends its locale, and a task handed to another computer from the desktop, Android or the iPhone carries the screen's language, so the Muse over there answers in it. Older clients send nothing and get the old behaviour; a fixed *Reply language* still wins.
- **The Sentinel asks in `auto` mode where it used to allow.** Once a conversation has read mail, a calendar, contacts or a file outside the workspace, a call that would send data to a host outside `sentinel.egress_allowlist` now asks in every mode; before, `auto` turned that question into an allow, so an unattended goal pass could read a private file and post it to an unknown host in silence. A call that carries a warning (`rm -rf`, `sudo`, code that reads the environment) asks in `auto` too, as the policy always said. `nanomuse daemon`, which has nobody to ask, declines such a step with a note and goes on. Taint is kept per conversation rather than per process, so a side chat that read a private file no longer makes every other chat ask. Around it: the vault redacts short secrets (a four-digit PIN) as whole words; a thread id cannot name a file outside the threads folder; a shell timeout stops the whole process tree; approvals see the programs inside `$(...)`; IMAP arguments are quoted; `open_app` refuses `shutdown`, `reboot`, `sudo` and a shell. Android's shell guard sees through `timeout`, `nice`, `sudo -u`, `ionice`, `env` and `xargs`, a path another device names stays inside the sandbox, and a hands run's Stop takes effect while an approval card is waiting ([docs/sentinel.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/sentinel.md)).
- **The hub and the relay, hardened on both ends.** The relay (0.23.0) gives each hub connection a bounded send queue and closes a device that stops reading with `4009 slow_consumer` instead of holding the device that was calling it; a bad key is answered with the `error` frame and close `4001` after the handshake, as the protocol says, where the apps used to see a network failure and retry for ever; a binary frame is answered, not dropped; a call nobody answers fails at the caller's next `ping`. A stored sign-in code is hashed with `CLOUD_SECRET` as its key, so the database alone shows nothing, and a relay that sends codes refuses to start without that secret. The allowance is counted the way the provider bills: cached prompt tokens at the cached rate, DeepSeek's night price between 22:00 and 8:00 Beijing time, a 720P or 1080P clip at its own price. A session key can no longer mint another; the request body limit is enforced as the body arrives; conversation sync keeps at most 2 000 live side conversations per account; the console's account pages read exactly the accounts they show. On the clients the hub keeps one connection, waits two minutes after `hub_paused`, stops knocking when the relay refuses the key or the device and says so under Devices, and every call to the relay has a deadline ([docs/hub.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/hub.md)).
- **The phones, besides.** iPhone: the sync tables survive a locked phone (they were written with the strictest data-protection class, so an app woken in the background could read them as missing and push every conversation again under new ids); pictures and clips go through the Network proxy; a wrong key is noticed when it is saved (*The provider refused this key (HTTP 401)*); a swipe in from the left edge opens the drawer; a one-off routine made after its time runs the next day; the NFC, Bluetooth and Face ID prompts are in every language; zero compiler warnings in the app's own files, enforced by CI. Android: screenshots from the hands are trimmed (the ten newest runs keep all of theirs, an older run its trace and last screen, past 200 runs the oldest goes); the Library shows the signed-in account's files only; another device can stop a task it asked the phone to run; a `notify` says when notifications are not allowed; dates follow the phone's locale; connector keys are masked while typed.
- **No dashes in anything a person reads.** Every sentence on every client, in the runtime's cards and refusals, in the ideas catalogue, the consoles, the READMEs in ten languages, the changelog and the notes of 0.1.1 to 0.1.41 reads with a comma, a colon, a full stop or parentheses where an em dash stood; a test on each client keeps it that way. In 简体中文 and 繁體中文 the relay is *nanoMuse Cloud* everywhere, the agent is 智能体 / 智慧體, and the relay 中继 / 中繼.

## Upgrade Notes

- **Android installs over 0.1.41 and keeps your data.** `nanoMuse-1.0.0-arm64.apk` (Android 8.0+, arm64; versionCode 43) is signed with the same key as every version before it. Verify with `sha256sum -c nanoMuse-1.0.0-arm64.apk.sha256`.
- **iPhone and iPad come through TestFlight.** Build 16 of 1.0.0 is on TestFlight; the public link delivers it once Apple's beta review has passed, and until then the build reaches the internal testers only. The screen row of the Models page stays disabled on the iPhone (your computer uses its own setting), and the pictures and clips pickers list, besides nanoMuse Cloud, only your providers on a DashScope host; a sentence under the picker now names the keys it cannot use.
- **The desktop installers are built by CI from the tag `v1.0.0`.** The Mac packages are not notarized: the first time, open the app from *System Settings → Privacy & Security → Open Anyway* (or right-click → *Open*). The Windows package is not signed: click *More info* and *Run anyway* once. On Linux prefer the `.deb`; the AppImage needs FUSE (`--appimage-extract-and-run` without). They arrive a little after the APK, and `SHA256SUMS-desktop.txt` lists every checksum.
- **The Sentinel's `auto` mode asks more.** A background pass (Hands-off mode, `--auto`) that read your mail, your calendar or a private file and then reaches a host outside the egress allowlist now puts an approval card in the Feed and waits, and so does a call with a warning (`rm -rf`, `sudo`); `nanomuse daemon` declines such a step with a note. A goal that used to run through unattended may now stop for you once; list the host under `sentinel.egress_allowlist` if that is what you want.
- **The nanoMuse Cloud provider row is no longer deletable** on Android and the iPhone, because that instance is the account. Signing out is under *Settings › nanoMuse Cloud* on both; the switch *Use nanoMuse Cloud models* on *Settings › Models* is the way to keep the account and stop using its models.
- **The relay is 0.23.0, and a sign-in code sent before the update no longer verifies.** Codes are now hashed with `CLOUD_SECRET` as the key, so a code that was sent by a 0.22.0 relay reads as *That code is not right* on the new one; asking for a new code is the way through. An operator's relay that sends codes will not start without `CLOUD_SECRET` set (the development key is only for a relay that prints codes to its own log). Everything else on the wire is as in 0.22.0: a 0.1.41 client works against the new relay unchanged; the hub gained the close code `4009 slow_consumer`, which an older client treats as a dropped connection and retries; `/v1/models` carries new price fields under `nanomuse.price_cny`; `/v1/sync/state` lists the side-conversation limit. New per-model settings for `CLOUD_MODELS` are in [cloud/README.md](https://github.com/nano-muse/nanoMuse/blob/main/cloud/README.md).
- **Runtime and web console:** `language` on `send` and `task` is optional, and a client that does not send it gets the old behaviour. `[cloud] models` is new and defaults to on; `[connectors.search] fallback = false` makes a failed search fail instead of asking DuckDuckGo as well. A `sync.json` and every other state file are written aside and moved into place. The provider sentences the runtime sends changed wording (no dashes), so a console built before this version shows them in English until it is updated.

## Community

nanoMuse is open source, free and non-profit. Sign in with a phone number or an e-mail and you get a starting allowance; the developer pays for it. The account page shows what is left and how to add more. When it is gone, use your own key or a plan you already pay for ([how](https://github.com/nano-muse/nanoMuse/blob/main/docs/own-key.md)); the key you add can take over any of the four jobs, and since this version the account can be switched off as a model source while you keep it for sync and your devices. With an account, the text of your main conversation is kept on nanoMuse Cloud so that your devices show the same chat, side chats only if you say so, and one switch in Data controls turns it off and deletes it; nothing is sold ([privacy policy](https://nanomuse.cn/privacy/)); delete the account whenever you want. The same relay runs on a server of yours: [docs/self-hosting.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/self-hosting.md).

1.0 is the first stable version, not the last word. We use it every day and still know where it is rough; tell us where it broke for you and what you want it to do. The [roadmap](https://github.com/nano-muse/nanoMuse/blob/main/docs/roadmap.md) says where help is wanted, and [docs/parity.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/parity.md) says what each client has. Thanks to everyone who tried a build and reported what broke, and to @aliabbas6622, whose pull request [#193](https://github.com/nano-muse/nanoMuse/pull/193) went through the relay's and the runtime's bounds and whose fixes are in this version. 🐉 **nanoMuse `1.0.0`「Keel」**：第一个稳定版。一个个人智能体，面向你的每一台设备；里面没有一样东西是我们自己不敢用的。

从 2026-09-25 起，每个版本都是预览版。四十个版本之后，这一套终于齐了：Android 和 iPhone 的手机 App，Mac、Windows 和 Linux 的桌面 App，网页控制台，以及开源的中继 nanoMuse Cloud，负责登录、让你的设备互相说话。一个账号贯穿所有设备，手机、桌面和浏览器看到的是同一条对话。手机上和电脑上都有「手」，看着屏幕替你操作，智能体和任何不可撤销的事之间隔着一道审批。十八家服务商任选一家用自己的 key，或者用账号自带的免费额度。全部在一个仓库里，GPL-3.0-or-later，非营利。

1.0 的意思是：这里有的东西按文档说的那样工作；更新能覆盖安装上一版、数据保留；三条线上协议（hub 帧、对话同步、操作器）有文档，落后一个版本的客户端照常能用；哪里还糙，我们用平实的话告诉你。它不表示做完了，[路线图](https://github.com/nano-muse/nanoMuse/blob/main/docs/zh/roadmap.md)还是那么长。0.1.41 之后的改动主要关于两件事，选择和信任：nanoMuse Cloud 可以作为模型来源关掉而不退出登录，主聊天跟着你选的模型走，模型选择器会折叠、能搜索，Sentinel 在 `auto` 模式下原来直接放行的地方现在会问，hub 和中继两头都加固了。

### 亮点

- **nanoMuse Cloud 是一个开关，不是一堵墙。** Android、iPhone 和桌面版的「设置 › 模型」第一项是「使用 nanoMuse Cloud 的模型」，网页控制台的 nanoMuse Cloud 卡片上有同一个开关；运行时读作 `[cloud] models = false` 和 `POST /api/cloud/models`。关掉后，账号的模型从每个选择器和手、图片、视频的自动顺序里退出，旁路调用（对话标题、压缩）不再走中继，唯一会花额度的是你明确点的「这次改用 nanoMuse Cloud」；登录、对话同步和你的设备都保留。对话模型还是账号的时候，关掉会被一句话拒绝，因为没有别的模型能回答。有自己 key 的手机或控制台现在退出登录也能用：登录页只在既没有账号也没有带 key 的服务商时才出现，并提供「改用自己的 API key」。Android 和 iPhone 上 nanoMuse Cloud 这家服务商不能再删除（删除就是退出登录）；它的页面说明原因并指向那个开关。
- **主聊天跟着你选的对话模型走。** 0.1.41 上在「设置 › 模型」选对话模型只决定新对话的默认，而主聊天从来不是新的，所以加了 key 的人看到旁聊都走自己的 key、主聊天在形象下面却还是 nanoMuse Cloud。Android、iPhone 和桌面版的主聊天现在跟着选择一起走；旁聊保留自己的模型；选择器下面那行写明了这一点；Android 还会带上这一组的思考深度。正在「这次改用 nanoMuse Cloud」的主聊天把这一轮在账号上走完，然后回到你的选择。
- **模型选择器会折叠长列表、能搜索**，每个客户端都是。每家服务商一组显示八个模型（目录里这一行的默认在最前，然后是正在用的，然后按服务商列出的顺序），多出来的收在「还有 N 个」里；各组加起来超过八个时，上面出现「搜索模型」，边打字边按模型 id 或名字过滤每一组，什么都不匹配时写「没有匹配的模型」。OpenRouter 或 SiliconFlow 不再把选择器变成一张没有尽头的单子。Android 上搜索词和展开的组能撑过旋转屏幕，「自动」和每一行都会告诉 TalkBack 和 VoiceOver 自己是不是选中的那个。
- **自己的 key 也能选思考深度（桌面版）。** 输入框的模型选择器原来只给 Cloud 已知的模型提供深度。服务商目录（`providers.json`，每个客户端都带的那份文件）现在按厂商和模型名记录厂商自己的文档是怎么控制深度的，并写明出处页面；桌面版按厂商的格式把这些档位告诉 harness：OpenAI、Kimi、MiniMax、硅基流动、火山方舟、xAI、Gemini 的 OpenAI 兼容层、Groq、Mistral 以及 Ollama 或 vLLM 上的 gpt-oss 用 `reasoning_effort`；DeepSeek 和智谱用 `thinking` 加 `reasoning_effort`；OpenRouter 用它模型列表里给出的 `reasoning.effort` 档位；Anthropic 用自适应思考加 `output_config.effort`。「服务商默认」什么都不发。早先版本保存的 key 在下次启动时拿到这些档位；手机读同一份目录，暂时忽略这个字段。
- **星标卡多了「我已经点过 Star」。** 在「去 GitHub 点 Star」和「暂不」旁边，每个客户端的每张卡片和每个星标行上，这个新按钮表示已经点过了；它和「去 GitHub 点 Star」都会让这台设备永远不再问，不管冷却期和剩下的询问次数。在 GitHub 上直接点过 Star 的人以前会被反复问，现在不会了。
- **桌面版会等慢的启动、知道自己的版本、给对的安装包。** 全新的 Windows 上，实时防护在第一次打开时逐个检查 App 的两万个文件，外壳等了 120 秒放弃并报「host 没有在 120 秒内公布地址」，host 几秒后才起来。外壳现在 host 进程还在就一直等：两分钟后显示「仍在启动」和 host 最后几行输出，十分钟后弹出「继续等」「复制详情」或「退出」。装好的 App 以前把自己当成 `0.0.0`（版本来自一个没人设的环境变量），于是每天的更新检查把每个版本都当成更新，hub 里也报 `dsh-nanomuse 0.0.0`；现在版本在构建时写进包里，比较的是纯数字。「关于」在 Linux 上给 `.deb`，只有正在从 AppImage 运行时才给 AppImage。Windows 上 Cursor 或 Claude Code 的工作区能正确读回 `C:\Users\me\app`，这也是 0.1.41 桌面构建失败的原因。设置页从一页跳到另一页时顶部有「返回 {页面}」；调用中继失败时是一句中英文都有的平实句子，而不是线上的原文；输入法还在组字时按回车不再发送。
- **回复跟随 App 的语言。** 系统提示原来只写最新一条消息的文字种类，所以英文控制台上一条短的或中英混杂的消息，有一半的机会得到中文回答。客户端现在可以随每条消息带上界面语言（`language`，BCP-47 标签，在 `POST /api/threads/{id}/send`、socket 的 `send` 帧和 hub 的 `task` 调用上）；提示先写这个语言，再写消息的文字种类。网页控制台发送自己的语言设置，从桌面版、Android 或 iPhone 交给另一台电脑的任务带着屏幕的语言，那边的 Muse 就用这种语言回答。旧客户端什么都不发，行为和以前一样；固定的「回复语言」仍然优先。
- **Sentinel 在 `auto` 模式下原来放行的地方现在会问。** 一旦某条对话读过邮件、日历、联系人或工作区之外的文件，一个会把数据发到 `sentinel.egress_allowlist` 之外主机的调用，现在在每种模式下都会问；以前 `auto` 把这个问题变成放行，所以一次无人值守的目标运行可能读了一个私人文件，然后悄悄发到一个不认识的主机。带警告的调用（`rm -rf`、`sudo`、读取环境变量的代码）在 `auto` 下也会问，策略一直是这么写的。没人可问的 `nanomuse daemon` 会附一条说明拒绝这一步，继续做剩下的。污点按对话记而不是按进程记，读过私人文件的旁聊不再让其他每条聊天都来问。周边：保险库把短密钥（四位 PIN）按整词遮掉；线程 id 不能指向线程文件夹之外的文件；shell 超时时整棵进程树一起停；审批能看见 `$(...)` 里的程序；IMAP 参数加了引号；`open_app` 拒绝 `shutdown`、`reboot`、`sudo` 和 shell。Android 的 shell 守卫能看穿 `timeout`、`nice`、`sudo -u`、`ionice`、`env` 和 `xargs`，另一台设备报的路径只能留在沙箱里，手在运行时按「停止」在审批卡等待期间也立即生效（[docs/sentinel.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/zh/sentinel.md)）。
- **hub 和中继，两头都加固。** 中继（0.23.0）给每条 hub 连接一个有上限的发送队列，不再读取的设备以 `4009 slow_consumer` 关闭，而不是拖住正在调用它的那台；错的 key 按协议在握手之后回 `error` 帧并以 `4001` 关闭，以前 App 看到的是网络故障然后永远重试；二进制帧会被回答，不再掉线；没人回答的调用在调用方下一次 `ping` 时就失败。存下来的登录验证码用 `CLOUD_SECRET` 做密钥哈希，光有数据库文件什么也看不出来；会发验证码的中继没有这个密钥就不启动。额度按服务商计费的方式计：命中缓存的提示词 token 按缓存价，DeepSeek 在北京时间 22:00 到 8:00 按夜间价，720P 或 1080P 的视频按各自的价。会话密钥不能再签发另一把会话密钥；请求体上限在数据到达时就执行；对话同步每个账号最多保留 2 000 条活着的旁聊；控制台的账号页只读它要显示的那些账号。客户端这边，hub 只保持一条连接，`hub_paused` 之后等两分钟，中继拒绝 key 或设备时不再敲门并在「设备」下写明，调用中继的每个请求都有时限（[docs/hub.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/zh/hub.md)）。
- **手机上的其他改动。** iPhone：同步表能撑过锁屏（它们原来用最严格的数据保护等级写入，后台被唤醒的 App 可能把它们读成不存在，然后用新 id 把每条对话再推一遍）；图片和视频走「网络」里的代理；保存 key 时就发现它是错的（「服务商拒绝了这把 key（HTTP 401）」）；从左边缘划入打开抽屉；过了时间才创建的一次性例程改到第二天运行；NFC、蓝牙和 Face ID 的提示有每种语言；App 自己的文件零编译警告，由 CI 保证。Android：手的截图会清理（最新十次运行全部保留，更早的只留轨迹和最后一屏，超过 200 次时删最旧的）；资料库只显示当前登录账号的文件；另一台设备能停掉它让这台手机做的任务；`notify` 会说明通知没有权限；日期跟随手机的区域设置；连接器的 key 输入时打码。
- **人读到的话里不再有破折号。** 每个客户端的每句话、运行时的卡片和拒绝语、灵感目录、各个控制台、十种语言的 README、整份更新日志和 0.1.1 到 0.1.41 的发布说明，原来是破折号的地方现在是逗号、冒号、句号或括号；每个客户端各有一个测试保证它不再回来。简体和繁体中文里中继一律叫 nanoMuse Cloud，agent 叫智能体 / 智慧體，relay 叫中继 / 中繼。

### 升级说明

- **Android 覆盖安装 0.1.41，数据保留。** `nanoMuse-1.0.0-arm64.apk`（Android 8.0+，arm64；versionCode 43）和之前每个版本用同一把签名。校验：`sha256sum -c nanoMuse-1.0.0-arm64.apk.sha256`。
- **iPhone 和 iPad 通过 TestFlight。** 1.0.0 的第 16 个构建在 TestFlight 上；公测链接在 Apple 的测试版审核通过后送达，在那之前只有内部测试员拿得到。模型页的「操作屏幕」一行在 iPhone 上仍然是灰的（电脑用它自己的设置）；生成图片、生成视频的选择器除了 nanoMuse Cloud 只列你在 DashScope 主机上的服务商，选择器下面现在有一句话写明哪些 key 用不上。
- **桌面安装包由 CI 从 tag `v1.0.0` 构建。** Mac 的包没有经过公证：第一次在「系统设置 → 隐私与安全性」里点「仍要打开」（或右键 → 「打开」）。Windows 的包没有签名：点一次「更多信息」和「仍要运行」。Linux 上优先用 `.deb`；AppImage 需要 FUSE（没有就加 `--appimage-extract-and-run`）。它们比 APK 晚一点到，`SHA256SUMS-desktop.txt` 列出了所有校验值。
- **Sentinel 的 `auto` 模式问得更多了。** 一次后台运行（放手模式、`--auto`）读了你的邮件、日历或一个私人文件之后再去连外发白名单之外的主机，现在会在动态里放一张审批卡并等待，带警告的调用（`rm -rf`、`sudo`）也一样；`nanomuse daemon` 会附一条说明拒绝这一步。以前能无人值守跑完的目标现在可能停下来问你一次；如果那就是你要的，把主机加到 `sentinel.egress_allowlist` 里。
- **nanoMuse Cloud 这家服务商不能再删除**，Android 和 iPhone 上都是，因为那一项就是账号本身。退出登录在两个平台的「设置 › nanoMuse Cloud」里；想保留账号但不用它的模型，用「设置 › 模型」里的「使用 nanoMuse Cloud 的模型」开关。
- **中继是 0.23.0，更新之前发出的登录验证码不再有效。** 验证码现在用 `CLOUD_SECRET` 做密钥哈希，所以 0.22.0 中继发出的码在新中继上读作「验证码不对」；重新获取一个即可。运维者自己的中继如果发验证码，没有设 `CLOUD_SECRET` 就不会启动（开发用的密钥只给把验证码打印到自己日志里的中继）。线上其他一切和 0.22.0 一样：0.1.41 的客户端对着新中继照常工作；hub 多了关闭码 `4009 slow_consumer`，旧客户端把它当作掉线重连；`/v1/models` 在 `nanomuse.price_cny` 下多了几个价格字段；`/v1/sync/state` 列出旁聊上限。`CLOUD_MODELS` 新增的每模型设置见 [cloud/README.md](https://github.com/nano-muse/nanoMuse/blob/main/cloud/README.md)。
- **运行时和网页控制台：** `send` 和 `task` 上的 `language` 是可选的，不发它的客户端行为不变。`[cloud] models` 是新的，默认开；`[connectors.search] fallback = false` 让失败的搜索直接失败，而不是再去问 DuckDuckGo。`sync.json` 和其他每个状态文件都先写到一旁再换上去。运行时发出的服务商句子换了措辞（去掉了破折号），所以在这个版本之前构建的控制台在更新前会以英文显示它们。
