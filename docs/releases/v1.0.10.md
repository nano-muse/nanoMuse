# nanoMuse 1.0.10 · Bridge

🐉 **nanoMuse `1.0.10` “Bridge”** lets an Android phone keep a screen task away from the display you are using, and helps every client return to commitments and sources that changed while you were away.

On Android 14 and newer, a compatible app can run on a separate display while your keyboard, chat and Stop control stay on the main screen. The six-step setup watches Android's switches, reads the one-time wireless debugging code through the accessibility service when allowed, and connects by itself. During a run, a secure floating preview shows the last safe frame until the next one is ready, while the originating chat shows the phase and step without exposing screen text or model reasoning. This work was inspired by [Mika](https://github.com/wangzan101/Mika); the wireless pairing and floating-window code adapted from Mika is included under Apache-2.0 with its notice in the APK.

The other thread is follow-through. The runtime, desktop and phones can notice a due commitment, an expected reply, a changed connected source or an update from a public project or researcher, then bring one relevant item back to the main chat. These checks are bounded, observe quiet hours and remain under the controls in Feed settings.

## Highlights

- **Android can operate a compatible app on a background screen.** Turn on *Settings → Hands → Background screen*, complete the guided wireless debugging setup, then name the app in a screen task. A draggable read-only window keeps Stop, pause and phone handover available. The chat that started the task shows safe live progress and stops only its own screen run.
- **Pairing is automatic when Android exposes the pairing window.** With accessibility enabled, nanoMuse reads the six-digit code and port from Android Settings and completes the local pairing without logging the code. An inline notification reply and a collapsed manual form remain as fallbacks. The private key stays in Android Keystore, and later runs try the saved port, the system property, mDNS and loopback discovery before asking for a port.
- **Feed and the main chat follow through on more of what you said.** Due commitments, expected replies, calendar conflicts and selected connected sources can produce a grounded draft, brief, checklist or short check-in. Android and iPhone can also follow public GitHub, publication and feed sources while the computer is off.
- **Device conversations and coding work keep their own context.** Android, iPhone and desktop can start a chat bound to a selected computer, recover results after reconnecting, show streamed steps and stop the exact remote call. Coding projects, sessions, tool details and file diffs use the same hub actions across the clients.
- **Long turns retain the request and sensitive outcomes.** The current request and the latest work stay in context after many tool calls. Completed sensitive actions remain visible after compaction, and an identical sensitive action asks again instead of being repeated after an uncertain result. Remembered cross-device approvals are tied to the exact device, chat, risk and action.
- **Local data and account boundaries are stricter.** Runtime exports use committed SQLite snapshots and reject replaced, linked or oversized files. Desktop account state is flushed through ordered atomic replacements with a recoverable private backup, conversation sync stays isolated across account changes, and mobile app and protected-chat locks clear authorization state when access changes.
- **The release includes reliability fixes across the project.** Android restores missing bundled shell files without resetting its sandbox, the desktop bounds logs and cached conversations and starts Windows command shims safely, Cloud keeps delayed admin requests and device identities in their original account, and the web console keeps the newest response when filters or account state change.

## Upgrade Notes

- **Android installs over 1.0.9 and keeps your data.** `nanoMuse-1.0.10-arm64.apk` supports Android 8.0 and newer on arm64 and carries versionCode 53. It is signed with the same key as earlier releases. Verify it with `sha256sum -c nanoMuse-1.0.10-arm64.apk.sha256`.
- **The background screen requires Android 14 or newer and compatible secondary-display support.** It also needs the accessibility service, floating-window permission, wireless debugging over Wi-Fi and a vision model. The phone must remain awake and unlocked. Phones that do not meet those checks keep the existing foreground screen mode.
- **iPhone and iPad come through TestFlight.** Build 34 is handed to the external group after upload and reaches the public link after Apple's beta review. Until then, the link installs the newest build that passed review.
- **Desktop installers are built only from tag `v1.0.10`.** Install over 1.0.9 and keep your settings. macOS packages are signed when the release credentials are available but are not notarised without them; use *System Settings → Privacy & Security → Open Anyway* when asked. Windows may require *Run anyway*. CI uploads nothing unless Windows, both Mac architectures and Linux all succeed and the complete asset set is present.
- **The relay is 0.32.0; self-hosted operators should update it with the runtime.** Existing 1.0.9 clients remain compatible. Keep the old containers and database copy until sign-in, model calls, hub reconnects, conversation sync and the admin console have passed your own smoke test.

🐉 **nanoMuse `1.0.10`「Bridge」**：Android 手机可以把屏幕任务放到你看不见的独立屏幕上继续执行，各端也会把到期或有变化的事情带回给你。

在 Android 14 或更高版本上，兼容的应用可以在独立屏幕里运行，你的键盘、聊天和停止按钮仍留在主屏。六步设置会实时检查系统开关，在权限允许时通过无障碍服务读取一次性的无线调试配对码并自动连接。任务进行时，安全小窗会一直保留上一张可显示的画面，等新画面加载好再替换；发起任务的聊天会显示阶段和步骤，但不暴露屏幕文字或模型推理。这个方案参考了 [Mika](https://github.com/wangzan101/Mika)。从 Mika 改编的无线配对和小窗代码按 Apache-2.0 许可使用，原始声明随 APK 一起提供。

另一条主线是持续跟进。运行时、桌面端和手机会留意到期事项、等待中的回复、已连接来源的变化，以及公开项目或研究者的更新，再把一条有用的信息带回主要聊天。检查次数有限，遵守安静时段，也可以在动态设置里关闭。

### 亮点

- **Android 可以在后台独立屏幕操作兼容应用。** 打开「设置 → 动手操作屏幕 → 后台独立屏幕」，完成无线调试引导，再在屏幕任务里指定应用。可拖动的只读小窗保留停止、暂停和在手机上接手。发起任务的聊天显示安全的实时进度，只会停止这个聊天自己的屏幕任务。
- **系统配对窗口可读取时，配对会自动完成。** 开启无障碍后，nanoMuse 从 Android 设置读取六位配对码和端口并在本机完成配对，不记录配对码。带输入框的通知和折叠的手动表单仍是兜底。私钥保存在 Android 密钥库中，后续运行会依次尝试保存的端口、系统属性、mDNS 和本机回环发现。
- **动态和主要聊天会继续跟进你提过的事。** 到期承诺、等待中的回复、日程冲突和选中的连接来源可以生成有依据的草稿、简报、清单或简短询问。电脑关闭时，Android 和 iPhone 也能继续关注公开 GitHub 项目、论文来源和订阅源。
- **设备聊天和编程任务保留各自的上下文。** Android、iPhone 和桌面端可以新建绑定到指定电脑的聊天，断线重连后找回结果，显示流式步骤，并停止准确的远程调用。不同客户端通过同一套 Hub 操作读取编程项目、会话、工具详情和文件差异。
- **长任务会保留原始要求和敏感操作结果。** 多次工具调用后，当前要求和最近的工作仍留在上下文里。压缩历史后，已经完成的敏感操作仍可见；结果不确定时，再次执行相同敏感操作会重新询问，不会直接重复。跨设备记住的授权会按设备、聊天、风险类别和完整操作分别保存。
- **本地数据和账号边界更严格。** 运行时导出使用已提交的 SQLite 快照，并拒绝被替换、链接或过大的文件。桌面账号状态按顺序原子写入，并保留可恢复的私有备份；切换账号时对话同步互不混用，手机的 App 锁和受保护对话在访问状态变化时会清理授权。
- **这个版本也带上了全项目的稳定性修复。** Android 会补回内置 Shell 缺少的文件而不重置沙箱，桌面端限制日志和会话缓存并安全启动 Windows 命令垫片，Cloud 会把延迟返回的管理请求和设备身份留在原账号，Web 控制台在筛选或账号变化后只采用最新响应。
