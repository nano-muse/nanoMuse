# nanoMuse 0.1.41 · Choice

🐉 **nanoMuse `0.1.41` “Choice”**: a person with a key of their own now chooses which model does each of four jobs, on every client, and nothing falls back to nanoMuse Cloud on its own.

People who added their own API key told us the same story: they could not find where to pick the model for the chat, for the hands, for the pictures or for the clips, so everything kept going through nanoMuse Cloud, and the free allowance was gone before they had tested their key. The entry points were there, but scattered and hard to find, and saving a key changed nothing by itself.

This version puts the four choices on one page, *Settings › Models*, on Android, the iPhone and the desktop, and the same four slots on the web console's *Connections* page. After a key is saved a card asks what it should handle; a row nobody set follows one order under an *Automatic* entry; and when a model of your own fails, the card offers *Use nanoMuse Cloud this time* for that one turn instead of switching behind your back. Around it: the desktop draws pictures through your own key and picks up a new hands model without a restart, the runtime gained connection routes for pictures and clips, the README opens with the film, the paper is on arXiv, and the docs site has a 简体中文 edition.

## Highlights

- **Settings › Models: four rows on every client.** *Chat* (the model that talks with you), *Operating the screen* (looks at the screen and acts for you; needs a model that can see images), *Making pictures* (portraits of your Muse and the pictures you ask for) and *Making clips* (short clips of your Muse). Each row shows `provider · model` and opens a picker: the *nanoMuse Cloud* group first while signed in, its recommended model marked, then one group per provider of your own holding only the models that fit; a provider without the capability does not appear in that row, and a row nothing covers says who could and offers *Add a provider*. A chat pick is the default for new chats. On Android the card at the top of Settings opens the page and *Settings → Hands* and the old *Image & video models* page use the same choices; on the iPhone it is the first card of Settings, with the screen row disabled (*Not on iPhone*: your computer uses its own setting); on the desktop it sits right after General and the two pickers left the nanoMuse Cloud page; on the web console *Connections* has the *Chat model* card, the *Hands model* select and new *Making pictures* and *Making clips* rows ([docs/own-key.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/own-key.md)).
- **After a key is saved, *Use it for*.** One toggle per thing the provider can handle (chat, the screen, pictures, clips), all on, each naming the model it would get; *Use it* switches those rows to the provider on the catalogue's default model for each job, *Not now* changes nothing, and saving alone no longer switches anything. Signed in, the card says nanoMuse Cloud keeps the rest.
- ***Automatic*, with one order.** The screen, pictures and clips rows open with an *Automatic* entry that says what it gives right now (*Currently nanoMuse Cloud · qwen3.8-27b*, say). When you have not chosen, a row follows the chat model's provider when it is one of yours and can do the job, else nanoMuse Cloud while signed in, else the first provider of yours that can. A choice you made always wins, and nanoMuse Cloud never steps in front of a provider you chose; picking *Automatic* drops a choice and lets the row follow the order again. Each device keeps its own choice, because keys never leave the device where they were entered.
- **No silent fallback.** When a model of your own fails under a turn, the error card offers *Use nanoMuse Cloud this time* while signed in: that one message is sent again through the account, the chat goes back to its model when the turn ends, and the Models page stays as it was. The desktop shows the same button after a failed studio round and a failed set of clips. Nothing switches on its own, so a misconfigured key shows itself and the allowance is not spent without you knowing.
- **Desktop: pictures through your own key, and the hands without a restart.** Pictures through a key of yours go straight to that provider (Model Studio's native image API, OpenRouter's image API, the OpenAI shape for OpenAI, Zhipu, SiliconFlow, Volcengine and xAI) and nothing is billed to the account; the avatar studio says *Drawn with provider · model* in place of the cost line, and the Media page's image row became a picker. The plugin now mounts the hands' MCP client itself: a change under *Operating the screen* restarts `nanomuse mcp` with the new model at the hands' next step, no cold restart, and a local server without a key is passed to the hands too ([docs/desktop.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/desktop.md)).
- **Runtime and web: every slot through the app layer.** `PUT /api/connections/gui` takes a catalogue id (`bailian`, `openrouter`, ...) as `PUT /api/connections/llm` does; the new `PUT /api/connections/image` and `/video` (with `GET`) write the `[image]` and `[video]` slots and answer what each resolves to, a provider without the capability refused with the one sentence. `[video] api_key` now goes to the video host. The web console's *Making pictures* and *Making clips* rows are these routes, with *Automatic* first and a *Currently provider · model* line under each control; the *Pictures and clips* field under the chat model is gone ([docs/configuration.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/configuration.md), [docs/web.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/web.md)).
- **The film, the paper, the News.** The README and its nine translations open with the 74 s film in place of the four screenshots; nanomuse.cn and the docs home play it too. The paper is on arXiv ([2610.08699](https://arxiv.org/abs/2610.08699), *nanoMuse: An Open-Source Personal Agent for Every Device You Own*): the READMEs carry the badge, a *News* list of milestones and a *Citation* section with the BibTeX, `CITATION.cff` names the paper, and the docs site's home pages have a *Paper* button. The docs site has a 简体中文 edition under `/zh/`, looks like the homepage, and nanomuse.cn has a 404 page of its own; the showcase has an embed mode for the frame on the homepage.
- **The relay's console, and the clients.** A sign-in for the app store's reviewer (`REVIEW_ADDRESSES`, `REVIEW_CODE`, both empty by default); the web console says why the relay refused, in Chinese and English; the star card's sentence can be set from the console (`star.text`, `star.text_zh`) and every client shows it; `X-Forwarded-For` is read only behind a proxy (`TRUSTED_PROXIES`); `cloud/.env.example` lists every setting. The desktop has a *Coding agents* page, a proxy for the model providers under Settings → nanoMuse Cloud → Network with *Restart now*, a Permissions page that lists every standing grant by risk tier, and *Report a bug* fills in the issue form's fields. The web console's first conversation happens in the chat, with a *Proxy (optional)* field on the own-key form; the runtime owns the first conversation and `PUT /api/connections/llm` takes `proxy`. On Android the lights while the hands work breathe instead of running; on the iPhone the sign-in sheet shows the app's mark and says which numbers get a code, the Devices list shows when an offline device was last seen, and a fresh install no longer flashes the home screen ([CHANGELOG.md](https://github.com/nano-muse/nanoMuse/blob/main/CHANGELOG.md)).

## Upgrade Notes

- **Android installs over 0.1.40 and keeps your data.** `nanoMuse-0.1.41-arm64.apk` (Android 8.0+, arm64; versionCode 42) is signed with the same key as every version before it. Verify with `sha256sum -c nanoMuse-0.1.41-arm64.apk.sha256`.
- **iPhone and iPad:** build 14 on TestFlight; the public link delivers it once Apple's beta review has passed. The screen row of the Models page is disabled on the iPhone; the pictures and clips pickers list, besides nanoMuse Cloud, only your providers on a DashScope host (Alibaba Cloud Bailian).
- **Desktop:** the chat and hands pickers moved from the nanoMuse Cloud page to *Settings → Models*, which links back; a hands change takes effect at the hands' next step, no restart. The hands speak OpenAI's shape, so an Anthropic or native Gemini key is named under the screen row and not offered for the hands. Pictures through a Gemini key go through Google's OpenAI-compatible layer: `images/generations` accepts `gemini-2.5-flash-image`, but Google's page does not document `images/edits` there, so the pose pictures of the avatar studio may not work with a Gemini key.
- **Web console and runtime:** an existing `[gui]`, `[image]` or `[video]` block in `config.toml` keeps working as it is; `[llm] image_model` and `video_model` still work. The new routes write `app-settings.json`, layered over the file as before. A runtime without the new routes shows no media rows in the console.
- **The relay stays at 0.22.0.** Nothing on the wire changed: the hub frames, the conversation sync and `/v1/models` are as in 0.1.40, and a 0.1.40 client works against it unchanged.
- **The desktop installers are not notarised.** On macOS open the app once from *System Settings → Privacy & Security → Open Anyway* (or right-click → *Open*); on Windows click *Run anyway*. They are on this release beside the APK, and `SHA256SUMS-desktop.txt` lists every checksum.

## Community

nanoMuse is open source and free. Sign in with a phone number or an e-mail and you get a starting allowance; the developer pays for it. The account page shows what is left and how to add more. When it is gone, use your own key or a plan you already pay for ([how](https://github.com/nano-muse/nanoMuse/blob/main/docs/own-key.md)); since this version the key you add can take over any of the four jobs, and the Models page shows which. With an account, the text of your main conversation is kept on nanoMuse Cloud so that your devices show the same chat, side chats only if you say so, and one switch in Data controls turns it off and deletes it; nothing is sold ([privacy policy](https://nanomuse.cn/privacy/)); delete the account whenever you want. The same relay runs on a server of yours: [docs/self-hosting.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/self-hosting.md).

This is a preview. We use it every day and know where it is rough; tell us where it broke for you and what you want it to do. The [roadmap](https://github.com/nano-muse/nanoMuse/blob/main/docs/roadmap.md) says where help is wanted, and [docs/parity.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/parity.md) says what each client has. 🐉 **nanoMuse `0.1.41`「Choice」**：用自己 key 的人现在可以在每个客户端上选定四件事各由哪个模型来做，而且什么都不会自己悄悄退回 nanoMuse Cloud。

添加了自己 API key 的人来信说的都是同一件事：找不到在哪里给对话、手、图片和视频选模型，于是一切还是走 nanoMuse Cloud，免费额度在 key 还没试上之前就用完了。入口其实都在，只是散落各处、不好找，而保存一把 key 本身什么都不改。

这个版本把四个选择放到同一页上：Android、iPhone 和桌面版都是「设置 › 模型」，网页控制台的「连接」页有同样的四个槽位。保存 key 之后一张卡片问它负责哪些事；没人设过的一行在「自动」下面按一个顺序走；你自己的模型失败时，卡片上给「这次改用 nanoMuse Cloud」，只管这一轮，不会背着你切换。围绕它的还有：桌面版用你自己的 key 画图、换手的模型不用重启，运行时多了图片和视频的连接路由，README 以影片开场，论文上了 arXiv，文档站有了简体中文版。

### 亮点

- **设置 › 模型：每个客户端四行。** 「对话」（和你说话的模型）、「操作屏幕」（看着屏幕替你操作，需要能看图的模型）、「生成图片」（形象的肖像，以及你要的图片）、「生成视频」（形象的短视频）。每行显示 `服务商 · 模型`，点开是选择器：登录时 nanoMuse Cloud 一组在最前，推荐的那个有标记，然后你的每家服务商一组，只列能做这件事的模型；没有这项能力的服务商在这一行里不出现，一行里什么都没有时写明谁能提供，并给「添加服务商」。对话这一行选了就是新对话的默认。Android 上设置顶部的那张卡打开这一页，「设置 → 手」和原来的「图像与视频模型」页用同一份选择；iPhone 上它是设置的第一张卡，「操作屏幕」一行是灰的（「不在 iPhone 上」：电脑用它自己的设置）；桌面版上它紧跟「通用」，原来 nanoMuse Cloud 页上的两个选择器搬了过来；网页控制台的「连接」页有「对话模型」卡、「手的模型」下拉和新的「生成图片」「生成视频」两行（[docs/own-key.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/zh/own-key.md)）。
- **保存 key 之后，「用它来做什么」。** 这家服务商能做的每件事一个开关（对话、屏幕、图片、视频），默认全开，每个写着会用上的模型；「就这样」把这几行切到这家服务商、用目录里每件事的默认模型，「暂不」什么都不改，只保存也不再切换任何东西。登录了的话，卡片会说其余仍由 nanoMuse Cloud 负责。
- **「自动」，一个顺序。** 操作屏幕、生成图片、生成视频三行打开时第一项是「自动」，写着它现在给的是什么（比如「当前为 nanoMuse Cloud · qwen3.8-27b」）。你没选时，一行先跟对话模型所在的服务商，只要它是你自己的、而且能做这件事；否则登录时用 nanoMuse Cloud；否则用你第一家能做这件事的服务商。你做过的选择永远优先，nanoMuse Cloud 不会排到你选的服务商前面；选「自动」会放弃一个选择，让这一行重新按顺序走。每台设备各自选，因为 key 不会离开录入它的那台设备。
- **不悄悄回退。** 你自己的模型在某一轮失败时，错误卡片上在登录状态下多一个「这次改用 nanoMuse Cloud」：这一条消息通过账号再发一次，这一轮结束后对话回到它自己的模型，模型页保持原样。桌面版在形象工作室的一轮失败和一组短视频失败之后也给同一个按钮。什么都不会自己切换，所以配错的 key 会显出来，额度也不会在你不知情时花掉。
- **桌面版：用自己的 key 画图，换手的模型不用重启。** 用你自己 key 画的图直接发给那家服务商（百炼的原生图像接口、OpenRouter 的图像接口，OpenAI、智谱、硅基流动、火山方舟和 xAI 用 OpenAI 的接口形状），不计入账号；形象工作室在费用那一行的位置写「由 服务商 · 模型 绘制」，媒体页的图片一行变成了选择器。插件现在自己挂载手的 MCP 客户端：在「操作屏幕」里改了之后，手的下一步就用新模型重启 `nanomuse mcp`，不用冷启动，本机没有 key 的服务也会传给手（[docs/desktop.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/zh/desktop.md)）。
- **运行时和网页：每个槽位都能从应用层设。** `PUT /api/connections/gui` 像 `PUT /api/connections/llm` 一样接受目录 id（`bailian`、`openrouter` 等）；新的 `PUT /api/connections/image` 和 `/video`（也有 `GET`）写 `[image]` 和 `[video]` 槽位，并回答每个槽位实际解析成什么，没有这项能力的服务商被拒绝并附那句话。`[video] api_key` 现在发给视频主机。网页控制台的「生成图片」「生成视频」两行走的就是这些路由，「自动」在最前，每个控件下面一行「当前为 服务商 · 模型」；对话模型下面的「图片和视频」一栏没有了（[docs/configuration.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/zh/configuration.md)、[docs/web.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/zh/web.md)）。
- **影片、论文、News。** README 和它的九个译本以 74 秒的影片开场，取代了四张截图；nanomuse.cn 和文档站首页也播放它。论文上了 arXiv（[2610.08699](https://arxiv.org/abs/2610.08699)，*nanoMuse: An Open-Source Personal Agent for Every Device You Own*）：各个 README 带上了徽章、一份里程碑 News 列表和含 BibTeX 的「引用」一节，`CITATION.cff` 指向论文，文档站首页有「论文」按钮。文档站在 `/zh/` 下有了简体中文版，样式和主页一致，nanomuse.cn 有了自己的 404 页；展示站有了给主页里的框用的嵌入模式。
- **中继的控制台，以及各个客户端。** 给应用商店审核员的登录（`REVIEW_ADDRESSES`、`REVIEW_CODE`，默认都为空）；网页控制台用中英文说明中继为什么拒绝；星标卡的那句话可以在控制台里设（`star.text`、`star.text_zh`），每个客户端都会显示；`X-Forwarded-For` 只在代理后面读取（`TRUSTED_PROXIES`）；`cloud/.env.example` 列出了全部设置。桌面版有了「编程助手」页，设置 → nanoMuse Cloud → 网络 里有给模型服务商的代理和「立即重启」，权限页按风险等级列出全部常设授权，「报告问题」会填好 issue 表单的字段。网页控制台的第一次对话在聊天里进行，自有 key 表单多了「代理（可选）」；运行时接管了第一次对话，`PUT /api/connections/llm` 接受 `proxy`。Android 上手干活时的灯光改为呼吸而不是跑动；iPhone 的登录页显示应用标志、说明哪些号码能收到验证码，设备列表显示离线设备最后一次在线的时间，全新安装不再闪现主屏（[CHANGELOG.md](https://github.com/nano-muse/nanoMuse/blob/main/CHANGELOG.md)）。

### 升级说明

- **Android 覆盖安装 0.1.40，数据保留。** `nanoMuse-0.1.41-arm64.apk`（Android 8.0+，arm64；versionCode 42）和之前每个版本用同一把签名。校验：`sha256sum -c nanoMuse-0.1.41-arm64.apk.sha256`。
- **iPhone 和 iPad：** TestFlight 上的构建 14；公测链接在 Apple 的测试版审核通过后送达。模型页的「操作屏幕」一行在 iPhone 上是灰的；生成图片、生成视频的选择器除了 nanoMuse Cloud 只列你在 DashScope 主机上的服务商（阿里云百炼）。
