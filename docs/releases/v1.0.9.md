# nanoMuse 1.0.9 · Tiller

🐉 **nanoMuse `1.0.9` “Tiller”**: a fix release the same day as Crew. The desktop starts again when you are signed in, the relay's console loads on a large record, and the runtime takes a budget for a task and recalls from the whole memory store.

1.0.8 went out this morning, and its desktop did not start for anyone who was signed in. The plugin pointed the *nanoMuse Cloud* provider row at the loopback door it opens for the relay and waited for that settings write while the plugins were still starting; the write waits for the plugins, so the Host never announced its address and the window sat on *Starting…* for good, with *nanoMuse is still starting* every ten minutes ([#701](https://github.com/nano-muse/nanoMuse/issues/701), fixed in [#703](https://github.com/nano-muse/nanoMuse/pull/703)). A fresh install was never affected, which is why the release check passed; everyone who had used 1.0.7 or signed in was. The same day the hosted relay's console stopped loading: the *Usage* page's table of the turns people ran on keys of their own read a week of them from the record itself, where a turn's provider and cached count sit behind its request and answer, and on 40 GB one call took minutes while holding the read connection's lock, so every page waited behind it ([#708](https://github.com/nano-muse/nanoMuse/pull/708)). Both are fixed here, together with three runtime changes that landed in between: a task can be given a budget and recall reads the whole memory store, both by @hobostay ([#697](https://github.com/nano-muse/nanoMuse/pull/697), [#696](https://github.com/nano-muse/nanoMuse/pull/696), for [#685](https://github.com/nano-muse/nanoMuse/issues/685)), and a contact's card folds its long lines, by @Yicheng-Mark ([#702](https://github.com/nano-muse/nanoMuse/pull/702)). Nothing changed on the phones; they move to 1.0.9 so every device reads the same version.

## Highlights

- **The desktop starts again when you are signed in.** The loopback door now asks for the port it had last, so the provider row is usually right as it is; when it is not, the row is rewritten once the Host is up, without being waited for. If your 1.0.8 sits on *Starting…*, quit it and install 1.0.9 over it: your settings, your chats and your sign-in stay where they were, and nothing else is needed ([#703](https://github.com/nano-muse/nanoMuse/pull/703), [#701](https://github.com/nano-muse/nanoMuse/issues/701)).
- **The relay's console loads on a large record.** The relay keeps the figures of a turn run on a key of the person's own in one small row (`own_figures`: account, time, provider, model, the three token counts), written with the turn and removed with it; the *Usage* page's table reads those rows in milliseconds instead of walking the record. The own turns kept before this version are filled in by a paced backfill after the restart, 200 a page, and the usage answer says `own_keys_pending` while it runs ([#708](https://github.com/nano-muse/nanoMuse/pull/708)).
- **A task can be given a budget: tokens, money, time, and the size of one request.** Off unless set. `[agent.budget]` in `config.toml` takes `max_total_tokens`, `max_cost_usd` (with your own per-million rates) and `max_seconds`; a task that reaches one stops with a sentence that says which, and the turn's usage goes to the audit log as a `task_budget` entry, only when a limit is set or reached. `agent.max_context_tokens` caps the approximate size of one request: tool results are shortened to a labelled head and tail and old exchanges dropped as whole groups; the saved conversation keeps the original text. By @hobostay ([#697](https://github.com/nano-muse/nanoMuse/pull/697), [#685](https://github.com/nano-muse/nanoMuse/issues/685)); [docs/runtime-budgets.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/runtime-budgets.md) has the details.
- **Recall searches the whole memory store.** Keyword search and recall by meaning read every memory, not only the newest 1,000 the listing shows, and a near-duplicate is found anywhere in the store, through the same search index, so a store with years of memories answers as fast as a new one. By @hobostay ([#696](https://github.com/nano-muse/nanoMuse/pull/696)).
- **A contact's card folds its long lines at 75 octets.** `render_vcard` wrote a long Chinese note as one oversized line, past what RFC 6350 allows, so a strict importer could reject or truncate it; the card now folds with the UTF-8-safe cut the calendar's lines already use, and parses back without loss. By @Yicheng-Mark ([#702](https://github.com/nano-muse/nanoMuse/pull/702)).
- **TestFlight.** Build 31 (1.0.8) was uploaded this morning and handed to the external group *nanoMuse Beta* for Apple's beta review; 1.0.9 goes up as build 32 to the same group and review. On the phone the two are the same app.

## Upgrade Notes

- **Android installs over 1.0.8 and keeps your data.** `nanoMuse-1.0.9-arm64.apk` (Android 8.0+, arm64; versionCode 52) is signed with the same key as every version before it. Verify with `sha256sum -c nanoMuse-1.0.9-arm64.apk.sha256`. Nothing changed on the phone in this version; installing it there can wait.
- **iPhone and iPad come through TestFlight.** Build 32 (1.0.9) is handed to the external group when it is uploaded and reaches the public link once its review has passed, the internal testers before that; until then the link installs the newest build that passed.
- **The desktop installers are built by CI from the tag `v1.0.9`.** Install over 1.0.8; your settings stay. The Mac packages are not notarized: the first time, open the app from *System Settings → Privacy & Security → Open Anyway* (or right-click → *Open*). The Windows package is not signed: click *More info* and *Run anyway* once. On Linux prefer the `.deb`; the AppImage needs FUSE (`--appimage-extract-and-run` without). They arrive a little after the APK, and `SHA256SUMS-desktop.txt` lists every checksum. A 1.0.8 on Windows that never finished starting cannot offer the update from its corner menu, so download the installer.
- **The relay is 0.31.1; a 1.0.8 client works against it unchanged.** For operators: the first start after the upgrade creates `own_figures` and a backfill fills it for the own turns already kept, in the background, 200 turns a page with a pause after each page; about fifteen minutes for a hundred thousand own turns on the hosted relay. Until it is through, the *Usage* page's own-key table is short of the older turns and the answer carries `own_keys_pending: true`. No new setting. [cloud/README.md](https://github.com/nano-muse/nanoMuse/blob/main/cloud/README.md) has the details.
- **The runtime's settings are the same unless you add a budget.** `[agent.budget]`, `[gui.budget]` and `agent.max_context_tokens` are new and off until set; nothing else in `config.toml` changes.

## Community

nanoMuse is open source, free and non-profit. Sign in with a phone number or an e-mail and you get a starting allowance; the developer pays for it. The account page shows what is left and how to add more. When it is gone, use your own key or a plan you already pay for ([how](https://github.com/nano-muse/nanoMuse/blob/main/docs/own-key.md)). With an account, nanoMuse Cloud keeps the record of your conversations with its models and the turns your own key answered, and what was decided around each turn as codes and never as words; your devices and the person running the relay can read it, nobody else; one tap under *Data controls* deletes it, and nothing is sold ([privacy policy](https://nanomuse.cn/privacy/)); delete the account whenever you want. The same relay runs on a server of yours: [docs/self-hosting.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/self-hosting.md).

🐉 **nanoMuse `1.0.9`「Tiller」**：和 Crew 同一天的修复版。登录过的桌面端又能启动了，中继的控制台在大记录上也能打开，运行时可以给一个任务定预算、在整个记忆库里找回忆。

1.0.8 今天早上发出去，它的桌面端对所有登录过的人都起不来。插件把「nanoMuse Cloud」那行服务商指向它为中继开的回环门，并在插件还在启动的时候等这次设置写入；而写入要等插件启动完，于是 Host 一直没有宣布地址，窗口永远停在「正在启动…」，每十分钟来一句「nanoMuse 还在启动」（[#701](https://github.com/nano-muse/nanoMuse/issues/701)，在 [#703](https://github.com/nano-muse/nanoMuse/pull/703) 修掉）。全新安装从来没有这个问题，所以发版检查放过了它；用过 1.0.7 或登录过的人都碰上了。同一天托管中继的控制台也打不开了：「用量」页里用户用自己 key 跑的轮次那张表直接从记录里读一周的数据，而一轮的服务商和缓存数都排在它的请求和回答后面，40 GB 的记录上一次查询要几分钟，还占着只读连接的锁，所有页面都排在它后面（[#708](https://github.com/nano-muse/nanoMuse/pull/708)）。这两件都在这个版本里修了，另外带上中间合进来的三个运行时改动：一个任务可以定预算，回忆在整个记忆库里找，都是 @hobostay 做的（[#697](https://github.com/nano-muse/nanoMuse/pull/697)、[#696](https://github.com/nano-muse/nanoMuse/pull/696)，对应 [#685](https://github.com/nano-muse/nanoMuse/issues/685)），联系人名片的长行会折行，@Yicheng-Mark 做的（[#702](https://github.com/nano-muse/nanoMuse/pull/702)）。手机上什么都没变；它们跟着升到 1.0.9，让每台设备读到同一个版本号。

### 亮点

- **登录过的桌面端又能启动了。** 回环门现在先要上次用过的端口，所以服务商那一行多半本来就是对的；不对的时候，等 Host 起来之后再改写这一行，不再等它。如果你的 1.0.8 停在「正在启动…」，退出它，把 1.0.9 装在上面：设置、对话和登录都原地不动，别的什么都不用做（[#703](https://github.com/nano-muse/nanoMuse/pull/703)、[#701](https://github.com/nano-muse/nanoMuse/issues/701)）。
- **中继的控制台在大记录上也能打开。** 中继把用自己 key 跑的一轮的数字单独存成一小行（`own_figures`：账号、时间、服务商、模型、三个 token 数），随这一轮写入、随它删除；「用量」页那张表读这些行只要几毫秒，不再翻记录。这个版本之前留下的自有 key 轮次由重启后的一个回填在后台补上，每页 200 条，补完之前用量接口带 `own_keys_pending`（[#708](https://github.com/nano-muse/nanoMuse/pull/708)）。
- **一个任务可以定预算：token、钱、时间，以及单次请求的大小。** 不设就不开。`config.toml` 的 `[agent.budget]` 接受 `max_total_tokens`、`max_cost_usd`（配你自己的每百万 token 单价）和 `max_seconds`；碰到其中一条的任务会停下并说明是哪一条，这一轮的用量作为 `task_budget` 条目写进审计日志，只在设了或碰到上限时写。`agent.max_context_tokens` 限制单次请求的大致大小：工具结果缩成带标记的头尾，旧的往来按整组丢弃；保存的对话保留原文。@hobostay 做的（[#697](https://github.com/nano-muse/nanoMuse/pull/697)、[#685](https://github.com/nano-muse/nanoMuse/issues/685)）；细节见 [docs/runtime-budgets.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/zh/runtime-budgets.md)。
- **回忆在整个记忆库里找。** 关键词搜索和按意思回忆读每一条记忆，而不只是列表显示的最新 1,000 条，近似重复也在整个库里找，走同一个搜索索引，所以存了几年记忆的库和新库一样快。@hobostay 做的（[#696](https://github.com/nano-muse/nanoMuse/pull/696)）。
- **联系人名片的长行按 75 字节折行。** `render_vcard` 把一条长的中文备注写成一整行，超过 RFC 6350 允许的长度，严格的导入方可能拒绝或截断；现在名片用日历已经在用的、不切开字符的 UTF-8 折法折行，折过的名片读回来不丢东西。@Yicheng-Mark 做的（[#702](https://github.com/nano-muse/nanoMuse/pull/702)）。
- **TestFlight。** 第 31 个构建（1.0.8）今天早上上传并交给了外部测试组「nanoMuse Beta」送 Apple 测试版审核；1.0.9 以第 32 个构建上传，进同一个组、同一道审核。在手机上这两个是同一个 App。

### 社区
